## RED

The RED phase writes the assertion-bearing tests, fixtures and helpers the spec
calls for, and the minimal production/helper seams they target as honest stubs
(each marked `// RED: replaced in GREEN`), so the crate compiles and every new
test fails on an assertion or an `Err` rather than at compile time.

### What is genuinely test-first here, and what is not

The spec has two parts, and only part of it is RED-shaped:

- **Part 1 (the measurement artifact)** is genuinely test-first. Its one
  assertion-bearing test — the spec says "a meta-guard test is hard; instead
  `tests/coverage_env.rs` asserts the helper itself" — drives a helper that does
  not exist yet, so it fails RED.
- **The `selfexe::open_self_from` seam (Part 2)** is genuinely test-first: the
  spec asks for a new injectable seam and a unit test of *both* arms, and the
  seam is stubbed so both arms fail RED.
- **The remaining Part 2 items** (cli dispatch arms, catalog miss branches,
  stubid error arms, error.rs Display, launch.rs hint selection, main.rs
  dispatch) are coverage *gaps* over code that already works. A test for
  already-working code passes the moment it is written, so it cannot be RED, and
  the spec itself scopes those to "after Part 1, re-measure and target whatever
  is still below ~90%" — i.e. they are driven by the post-fix measurement, which
  is a GREEN activity. Writing them now (green on arrival) would violate the RED
  contract, so they are deferred to GREEN rather than padded in here.

### Files added

- `tests/common/coverage.rs` — the `preserve_coverage_env(cmd)` helper and its
  `preserve_coverage_env_value(cmd, value)` seam, both RED stubs (no-op body).

- `tests/coverage_env.rs` — the unit test of the helper.

## GREEN

The GREEN phase fills the two RED stubs, threads the coverage-env fix through
every artifact/stub spawn (Part 1), and adds the genuine in-process tests the
post-fix re-measurement showed still needed (Part 2). All gates are green over
the GREEN tree, both feature flavors.

### What was implemented

**Part 1 -- the measurement artifact.**

- `tests/common/coverage.rs::preserve_coverage_env_value` now sets
  `LLVM_PROFILE_FILE` on the command when the parent carries one and touches
  nothing else; `preserve_coverage_env` reads the parent's value and delegates.
  A second overload, `preserve_coverage_env_assert`, does the same one thing for
  an `assert_cmd::Command` (a distinct type the std-`Command` helper cannot
  accept), so the CLI-spawning tests are routed too.
- Every `env_clear()` spawn of the ginary artifact/stub is routed through the
  helper: the std-`Command` sites (`tests/common/artifact.rs`, `built.rs`,
  `erl.rs`, `tests/artifact_real.rs`) via `preserve_coverage_env`, and the
  `assert_cmd::Command` sites (`tests/cli.rs` x2, `tests/otp_cli.rs`, and four
  `tests/regressions/*`) via `preserve_coverage_env_assert`.
- No cargo-llvm-cov flag change is needed. It exports
  `LLVM_PROFILE_FILE=.../target/ginary-%p-%8m.profraw`; the `%p` is the process
  id, so every inheriting subprocess writes its own unique `*.profraw` and
  `cargo llvm-cov report` merges them automatically. `--include-ffi` and friends
  are irrelevant -- the only thing that was lost was the inherited variable, and
  re-threading it is the whole fix. The `cov` mise task and the CI coverage job
  are unchanged.

**Part 2 -- genuine tests for truly-untested code.**

- `src/selfexe.rs`: `open_self_from` now opens `proc_path`, reads its link
  target for the reported path (falling back to `proc_path` itself), and calls
  `fallback` only when the open fails; `open_self` is refactored onto it. Both
  arms are unit-tested (the two RED tests).
- `src/stubid.rs`: an in-module test runs the compile-time-only `marker`/`put`/
  `put_u32` const fns at run time and round-trips the result through `scan`, so
  the digit-writing of `put_u32` in particular is asserted (a wrong `f` value
  would not parse back to `FORMAT_VERSION`); a second test drives `put_u32`
  through its multi-digit loop directly, since this build's format version is a
  single digit. stubid rose from 68.00% to 99.41% lines.
- `src/error.rs`: a test asserts every `LauncherError` variant exposes its cause
  through `std::error::Error::source`. error rose to 100.00% lines.
- `tests/catalog.rs`: `lookup`'s own version-miss, a document missing
  `schema_version`, a schema-1 document whose entry fails to deserialize, a
  non-numeric version component compared as text, `flag_path` for each origin,
  and a miss against an empty catalogue naming `nothing at all`.
- `tests/cli.rs`: `inspect --launch-plan --json` (the JSON launch-plan report)
  and `elf deps` in text form over two binaries (the per-file separator and
  block layout). cli rose from 92.52% to 94.59% lines.

semantics, so none was altered.

### 90.5% was not reached honestly; the resisting modules

The spec asked for a 90.5% margin and said, if that is not honest, to STOP and
report which modules resist in-process testing rather than pad. The honest total
is 90.26% -- over the 90% gate, 0.24 point under the 90.5% margin (~38 lines).
The uncovered remainder is dominated by code that no deterministic in-process
test on this platform reaches:

- **`catalog.rs` (73.66%, 392 missed lines)** -- almost all of it is the OTP
  *repack* pipeline: `repack_one`, `upstream_bytes`, `release_asset`,
  `unpack_upstream`, `strip_beams`, `openssl_version`, `pack_runtime`,
  `read_or_new`, `write_catalog`. The `tests/otp_repack.rs` suite drives
  `repack_with` through an injected inspection seam over an offline fake, which
  covers the pipeline's *decisions*; the real-tarball byte paths (a genuine
  multi-hundred-megabyte upstream OTP download, unpacked and stripped with the
  real tools) are what remain, and they are the pipeline's own end-to-end job,
  not a unit.
- **`sign_macos.rs` (87.50%, 67 missed)** -- the Mach-O code-signing paths are
  macOS-only and cannot execute on this Linux runner.
- **`assemble.rs` (86.40%), `strip.rs` (82.81%), `cache.rs` (89.80%),
  `stub.rs` (81.94%)** -- the residue is failure-injection error arms (an I/O
  error mid-assemble, a strip that the tool rejects, a cache directory that
  cannot be created) and object-format branches for targets other than the
  host. Each would need either a fault seam that does not exist or a
  cross-target/cross-OS fixture.
- **`selfexe.rs` (74.07%)** -- the residue is the `#[cfg(windows)]` `open_self`
  (compiled out on unix) and the `else { panic!(..) }` arms of the tests
  themselves, which only execute on a failure that does not happen.

None of these was padded with a vacuous test, and the CI gate stays at 90%.
Whether to invest in a real repack e2e (a large, network-bound fixture) to reach
the 90.5% margin is left for the reviewer to decide.

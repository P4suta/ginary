### 1 — the A4 fix-round prose claimed more mutation evidence than it recorded (low)

`docs/dev/log/A4.md`'s fix round opens by naming three tests that could not fail against the code

The account order lives in exactly one place, `write_build` in `src/cli.rs`:

```rust

    text.push_str(&explain.closure);
    text.push('\n');

```

Swapping the two `push_str` calls — the staged account printed before the closure account — is
the whole mutation, and `GINARY_REQUIRE_TOOLCHAIN=1 cargo test --test e2e_hello
explain_prints_both_accounts` then fails on the assertion, against a real `gleam`, `erl` and
`strip` build of the `hello_ffi` fixture:

```text

  tests/e2e_hello.rs:249:5:
the accounts come in build order and before the report:
```

The test finds `origin` (the closure table's header), `bytes` (the staged table's) and
`artifact: ` by position in one stream and asserts `closure < staged < artifact`, so the mutation
is caught by the first of the two comparisons; the artifact line is still last, which is why only
the ordering half moves. The mutation was reverted immediately and `git diff src/cli.rs` is empty.

`docs/dev/log/A4.md` now names the third test in full rather than "the two halves of the
`--explain` ordering", says "all three mutations", and carries the failure above beside the other
two, with a pointer to this section saying that the third was run after the review rather than
during the fix round. No claim in that log is now larger than its evidence.

### What was implemented

**`src/config.rs`** — the six runtime keys are read and linted. `vm_args()`, `sys_config()`,
`filename_encoding()` and `encoding_flag()` are accessors of the same shape as `output()` and
`compression_level()`, so `ToolsConfig::default()` stays derivable. `filename_encoding_flag`
maps `utf8`/`latin1`/`auto` onto `+fnu`/`+fnl`/`+fna` and nothing else onto anything.
`args_file_flag_reason` gives `-args_file` and `-noinput` their own reasons and delegates the
other five to `erl_flag_reason`, so the args file lint and the `erl_flags` lint state one rule
once. `env_name_reason` refuses the `ERL_` prefix and the five derived names.
`tokenize_args_file` is a character scanner with three pieces of state — the token being built
with the line it started on, the open quote, and whether a comment is running — and
`lint_args_file` is a loop over its output. `validate_sys_config` goes through
`appfile::parse_terms` and turns a `ParseError` into `file:line:col: expected …, found …`; a
file that parses and is not exactly one list is `SysConfigShape`, and zero terms is refused
rather than read as `[]`.

`ToolsConfig::validate` gained the encoding and `env` checks, which is why both are enforced on
the parse path *and* on `BuildOptions::merge` without either being written twice. The two path
settings are deliberately **not** validated there: whether a file exists and what is in it is a
question about a tree, and everything in `config.rs` is pure. `BuildOptions::merge` resolves a
flag path as typed and a table path against the project, and `distribution` is `flag || table`
because a boolean flag has one direction.

**`src/manifest.rs`** — `LaunchSpec::validate` checks `args_file` and `config` exactly as it
checks `bindir`, `boot` and every `pa` entry. `format_version` stays 1: all six fields carry a
serde default.

**`src/launch.rs`** — the argv order of the spec, with the args file first. The removal list is
now built *before* the set list, so `launch.env` can be filtered against it: a name the scrub
removed is never set, whatever the manifest says. `HEART_COMMAND` is built as an `OsString` so a
user argument that is not valid UTF-8 survives into it. Two new public items serve `selftest`:
`halt_plan`, which swaps the `-eval` value for `HALT_EVAL` and truncates at `-extra`, and
`run_bounded`, which spawns, polls and kills at the deadline, reporting a typed `RunIssue`.

**`src/cache_lock.rs`** — `SharedLock::acquire` opens `<entry>/.lock`, clears `FD_CLOEXEC` with
`rustix::io::fcntl_setfd` and takes `LOCK_SH`; `try_exclusive` takes `LOCK_EX | LOCK_NB` and
leaves `FD_CLOEXEC` alone, because nothing execs while it is held.

**`src/cache.rs`** — `prune_days`, `prune_app`, `prune` and `uninstall`. `prune_app` considers
only complete entries: a directory with no `ginary.json` has no age and is the sweep's business.
Removal is rename-aside-then-remove, ADR 0005's own move, and a removal that fails **after** the
rename puts the entry back — a cache entry the launcher can still hit beats a directory nobody
will ever look at again.

**`src/launcher.rs`** — `prune_siblings` between the preflight and the launch, then
`SharedLock::acquire`, then the plan. The lock is dropped explicitly on the two paths that do
not exec, and inherited on the one that does. `GINARY_CMD` grew `selftest` and `uninstall`, and
`render_prune` is the one renderer both `uninstall` and `ginary cache prune` print through.

**`src/assemble.rs`** — `StagedRoot::add_file` writes one more file into the staged tree and
into `ginary.stage.json`. It has to touch the listing: the listing is what `payload::pack` packs
from and what `check_tree_is_listed` checks the tree against, so a file it did not name would be
either packed and undescribed or dropped without a word.

**`src/bundle.rs`** — `stage_runtime_files` reads, lints and stages the two files before
stripping and before the tree is measured, so both are in the size report and in the artifact.
`runtime_bins` adds `epmd` for `distribution` and `heart` for `heart`. `BundleError::RuntimeFile`
is separate from `BundleError::Config` because the headline has to be right: the manifest parsed,
and what did not hold up is a file it pointed at.

**`src/cli.rs`** — `ginary cache prune [--days N] [--all] [--app NAME]` and the three `build`
flags. `prune` resolves the cache root rather than preparing it, so pruning a cache that was
never created does not create one.

#### 1 — `tests/launcher.rs::a_failing_prune_never_fails_the_launch` planted its sibling too early

The test planted a thirty-day-old sibling, ran the artifact once to extract, and then chmod'ed
the sibling to `0o500` to make it unremovable:

```rust
let old = plant_entry(&artifact.app_dir(), "0000000000000000", DAY * 30);
ok(&artifact.run().output());

// Extract first, then make the entry unremovable, then run again.
std::fs::set_permissions(&old, std::fs::Permissions::from_mode(0o500))
    .expect("make the sibling unremovable");
```

That first run prunes, as every run does and as
`an_old_sibling_is_pruned_by_the_next_run_and_the_new_entry_is_not` in the same file requires. So
the sibling was already gone by the time `set_permissions` ran, and the test failed in its own
setup:

```text
thread 'a_failing_prune_never_fails_the_launch' panicked at tests/launcher.rs:1570:10:
make the sibling unremovable: Os { code: 2, kind: NotFound, message: "No such file or directory" }
```

The two lines were swapped so the sibling is planted **after** the extracting run, which is what
the test's own comment says it wanted ("Extract first, then make the entry unremovable, then run
again"). Nothing else changed: the same four assertions still run, and the closing pair — restore
the mode, run again, assert the sibling is gone — still proves that the survival above is the
failure being tolerated rather than pruning never happening.

#### 2 — the two `tests/cache_lock.rs` release assertions now poll

`a_shared_lock_blocks_an_exclusive_one_until_it_is_dropped` and
`try_exclusive_succeeds_on_a_free_entry_and_fails_on_a_held_one` each drop a `SharedLock` and
then assert immediately that the entry is lockable. Both failed under the parallel harness and
passed with `--test-threads=1`, which is the file's own subject observed from the wrong side: the
descriptor is deliberately **not** close-on-exec, so a `fork` another test in the same binary
makes while the lock is held carries a copy of it, and the lock outlives the drop until that
child exits. `HeldLock`'s `flock -x … sh -c 'read line'` is exactly such a child.

Nothing about that is wrong in the launcher — it execs immediately after acquiring, so no second
copy of the descriptor can exist — and nothing about it can be fixed from inside a test binary
that forks. Both assertions became bounded waits (`wait_until_unlocked`, and a ten-second poll
around `try_exclusive`) with a comment saying why. The claim is unchanged: a released lock leaves
the entry prunable. Only "at once" became "within the budget", and only because the harness can
hold a copy the production path cannot.

The consequence is recorded in ADR 0010 under `Consequences`, so the next reader of that file
meets it as a property of the design rather than as a flaky test.

### The flock proof

`tests/launcher.rs::the_shared_lock_outlives_the_launcher_and_dies_with_the_runtime` is the
executable form of ADR 0010's central claim, and it passes. It runs a `SyntheticArtifact` whose
`erlexec` stub is `sleep 5`, then asserts with util-linux `flock(1)` — not with
`ginary::cache_lock` — that `flock -n -x <entry>/.lock` **fails** while the child runs and
**succeeds** after it is killed. Nothing of ginary is alive at the moment of the first assertion:
the launcher has already `execve`d, so a lock that had not survived `execve` would be gone.

`a_finished_run_leaves_the_lock_file_and_no_lock` is the other half: the file stays with the
entry it belongs to, and nothing holds it.

### Two behaviours worth a reviewer's eye

**A selftest's child writes to `/dev/null`, not to standard output.** The run step spawns the
runtime with `Stdio::null()` on stdout, because the report is three parsable lines and a runtime
that greeted the world would make them unparsable —
`ginary_cmd_selftest_extracts_checks_and_runs_a_halt` asserts the whole of stdout. Standard error
is inherited, because a runtime that cannot boot says why there and that is the point of running
it.

**An entry whose directory cannot be written is `kept (locked)`, not renamed.** `try_exclusive`
creates `<entry>/.lock`, so an entry with mode `0o500` cannot be locked and is skipped — which is
the documented "a lock that could not be taken is a leave-this-alone", and is what makes
`a_failing_prune_never_fails_the_launch` observe a sibling that is still whole rather than one
renamed aside and abandoned.

### What changed

- `src/cache_lock.rs` — `SharedLock::acquire` takes `LOCK_SH | LOCK_NB` and retries for
  `SHARED_LOCK_BUDGET` (500 ms, a new public constant) before giving up. Nothing on either side
  of the lock blocks now.
- `src/launcher.rs` — `lock_entry` takes the lock and then re-checks `<entry>/ginary.json`,
  extracting once more and locking again when a prune took the entry in the window; a `lock_retry`
  trace record says so, and a second disappearance is `EXIT_CACHE` naming the entry. The
  `before-lock` fault point makes the window deterministic.
- `src/launch.rs` — `HEART_COMMAND` is built out of `shell_word`, which single-quotes any element
  a shell would split or expand and leaves ordinary paths and arguments alone; `launch.env` now
  skips every name the launcher has already decided, `HEART_COMMAND` included, so a hand-written
  manifest cannot append a second value that wins; `run_bounded` kills and reaps on the `Wait`
  error path.
- `src/cache.rs` — `uninstall` removes only what the cache wrote (`<key>` entries and the
  `.<key>.tmp-`/`.corrupt-`/`.trash-` residue), so an `erl_crash.dump` survives it and is in
  neither column; `prune_app` reports an entry it could not rename as `kept`, with the new
  `KeptReason::Unremovable`, which `uninstall` uses for the same case; both record `removed_paths`
  and `kept_paths` in the `prune` trace record.
- `src/config.rs` — `ConfigError::ArgsFileQuote` and `ConfigError::UnreadableFile`; the tokenizer
  reports the line a quote was left open on and `lint_args_file` refuses the file before it reads
  a single token out of it.
- `src/bundle.rs` — `read_runtime_file` tells `NotFound` from everything else and says what

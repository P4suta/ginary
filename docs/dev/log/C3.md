### 1 — a special file named by `--stub` produced half a sentence twice (low)

C2 stopped `stub::locate` from folding every non-file into "the stub <path> is not there" and gave
`StubError::NotAFile` a `found` field, documented as "the tail of a sentence". The sentence around
it read

```rust
"the stub {} is {found} rather than a file; `--stub` names the stub binary itself"
```

and `describe_file_type` answered with a noun phrase for one branch and a negation for the other:

```rust
if kind.is_dir() { "a directory" } else { "not a regular file" }
```

Only the first of those composes. A directory read "is a directory rather than a file", which is
the sentence C2 tested and snapshotted; everything else — a fifo, a unix socket, a device node,
which is what is left once `metadata` has followed the symlinks — read

```
the stub /dev/null is not a regular file rather than a file; `--stub` names the stub binary itself
```

That says one thing twice and contradicts itself doing so. It is cosmetic, which is why C2's review
filed it low, but it is the message a person reads at the moment they have already typed something
wrong, and the C2 branch exists precisely so that moment is not spent re-reading a spelling that is
correct.

RED first. `tests/regressions/c2_a_special_file_stub_said_not_a_regular_file_rather_than_a_file.rs`
runs `stub::locate` against four paths and asserts of each message that it does not contain
`not a regular file rather than a file`, that it names the file type, and that the remedy clause
survives:

| path | expected wording | before the fix |
| --- | --- | --- |
| a fifo (`mkfifo`) | `is not a regular file` | FAILED |
| a unix socket (`UnixListener::bind`) | `is not a regular file` | FAILED |
| `/dev/null` | `is not a regular file` | FAILED |
| a directory | `is a directory rather than a file` | ok |

Three of the four failed with the doubled clause, and the fourth passed, which is the point: the
directory case is the one wording that was already right and the fix must not move it.

The fix gives the clause to the answer that needs it rather than to the sentence that cannot know
which answer it has. `describe_file_type` now returns `"a directory rather than a file"` or
`"not a regular file"`, and `Display` writes `"the stub {} is {found}; ..."`. The rendered
directory sentence is byte-identical to C2's, so `tests/snapshots/stub__stub_error_messages.snap`
is unchanged — the only edit in `tests/stub.rs` is that the case it constructs by hand now uses
the string `describe_file_type` actually produces, so the snapshot is a sentence a user can get
rather than one the test invented. The field's doc comment says where the contrast lives now, so
the next caller does not re-add it outside.

A fifo, a socket and a device node are all still one answer rather than three: `metadata` follows
symlinks, so what is left after "a directory" cannot be a dangling link, and naming which of the
three it is would not change what the reader does about it. What was wrong was the grammar, not
the granularity.

### Four decisions

**No stub subcommand.** `CLAUDE.md` forbids a command that appears in the CLI and does not work,
so `ginary otp` was *not* added to `src/cli.rs`. The thirteen tests in `tests/otp_cli.rs` therefore
fail on `error: unrecognized subcommand 'otp'` — an assertion about what the real binary printed,
not a compile error, and exactly the failure a missing command should produce. GREEN adds the
command and the same thirteen assertions become the contract.

**Two seams, both the shape C1 already uses.** The pipeline's own check that an upstream asset is
really for the target it was requested as reads a `beam.smp`, and so does the catalogue arm of
`erts_source`. A fixture runtime carries a shell script there, so both take the inspection as a
parameter: `catalog::repack_with` and `erts_source::resolve_in_with`, beside the existing
`erts_source::resolve_with`. Everything above the ELF reader is then reachable on a machine with no
cross-built emulator and no 42 MB download.

**Snapshots are written by hand, not accepted.** `docs/dev/testing.md` says accepting a snapshot to
make a red test pass is the same defect as weakening an assertion. Both `.snap` files were authored
as the contract GREEN has to meet: `catalog__catalog_json.snap` is the serialisation of the fixture
catalogue produced by the *builder* in `tests/common/catalog.rs` (`serde_json`, never
`Catalog::to_json`, which is the writer under test), and `otp_cli__otp_list_table.snap` is the
table `ginary otp list` is being asked to print, down to the column widths. Neither `.snap.new`
exists, because neither assertion is reached yet.

**The ADR is 0013, not 0012.** The spec named `0012-local-first-otp-catalog.md`; 0012 is already
`stub-identity-and-feature-split`, taken by C2. `tests/smoke_matrix.rs` pins
`docs/adr/0013-local-first-otp-catalog.md` and its entry in `docs/adr/README.md`.

**No dependency was added.** The RED stubs fetch nothing, and `CLAUDE.md` forbids a dependency the
milestone does not yet use. The test server is hand-rolled std, and the fixtures use `tar`,
`flate2`, `zstd`, `sha2` and `hex`, which are already `[dependencies]` and are therefore visible to
the test targets. The `ureq` choice was verified rather than assumed and is recorded here for
GREEN: `ureq` 3.4.0's optional dependency list holds `rustls-platform-verifier ^0.7.0`, so the
`platform-verifier` feature exists in the version that will be pinned and
`rustls-native-certs` is not needed. `flate2` is already in the tree, so ureq's `gzip` feature adds
no new crate.

### Three decisions that are not in the RED report

**1 — `OtpReq::Exact` carries the host release.** `an_entry_older_than_the_host_is_refused_by_the_selection_itself` asks `select` to refuse an OTP 28 entry on a machine that compiles with 29,
through an `Exact` request — and the RED enum gave `select` no way to know what the host release
was. Discovering it inside `select` would have made a pure lookup run `erl`. The plan's own
sketch is `OtpReq{version: VersionReq::Host(release)|Exact(String)}`, a *request* that carries
more than the version, and `Host(u32)` already carries the release; `Exact` now carries it too.
See "GREEN / test corrections".

**2 — `lookup` is `select` without the version rule.** `ginary otp list`, `fetch` and `path`
answer questions *about* a catalog rather than building anything, and they run on machines whose
`erl` this process has no business starting. They call `Catalog::lookup`, which resolves version,
target and variant and lists what is there at whichever level it failed; `select` is `lookup` plus
the release guard, and the build is the only caller that has a host release to apply.

**3 — the repack strips the modules.** The measurement the spec asked for came back at 1013
modules per tree carrying `Dbgi`, which is 43.6 MB of the 62 MB a tree unpacks to. They are
stripped in the pipeline, by the *host's* Erlang through `crate::strip` — a `.beam` is portable
and an emulator is not, so one x86-64 Erlang strips the aarch64 tree as readily as its own — and
verified by the same rules a staged tree is: no `Dbgi`, no `Docs`, a `Code` chunk still there.
It takes each tarball from about 35 MiB to about 13 MiB. The trade is stated in the log entry
below rather than hidden: a `--no-strip` build now gets a runtime whose *OTP* modules carry no
debug information, because they never arrived with any.

### Three things outside `src/catalog.rs` that a working cross build needed

The first two are faults; the third is a stale claim.

Neither is in the spec, and both stop an aarch64 artifact from being built at all, so both are
part of "full cross-Linux artifacts".

**`strip` cannot read a foreign ELF.** binutils is built for a set of architectures; this
machine's answers `Unable to recognise the format of the input file` for an aarch64 binary, which
`strip_elf` turned into `StripError::StripFailed` and a failed build. A file whose machine is not
this one is now left alone with a counted, reported reason — upstream ships those binaries
stripped, so nothing is lost but the claim that they were stripped here.

Both new branches shipped with no test of their own, which the review caught: see finding 7 under
"Fix round 1". `bundle::beam_stripper` below was in the same position and is covered there too.

**A cross runtime's `bin/erl` cannot run here.** `beam_lib:strip_files/1` was run through the
*bundled* runtime's `erl`, which for an aarch64 tree execs an emulator this kernel will not load.
`bundle::beam_stripper` hands the host's installation to the strip phase whenever the runtime is
for another target; the modules are the same modules either way.

**`ginary doctor` said the catalog was not here yet.** `ErtsSourceSpec::milestone` reported a
milestone for `catalog` and `tarball:`, which is what the targets table prints as `not yet`. Both

That last sentence was half the story, and the review found the other half: they refused both
*naming the catalog milestone*, which had already shipped. See finding 1 under "Fix round 1".

now true; the fixture helper's doc, which is not the pipeline, says what it actually is and points
at the test that holds the pipeline to the rule.

`dist/otp` was repacked from the assets already in `dist/otp/.upstream` — offline, no download —
so the committed record matches what this code produces. `SOURCE_DATE_EPOCH` was kept at

The extracted runtimes were then removed from `~/.cache/ginary/otp` and `tests/e2e_cross.rs` run

containers rather than taken on the pipeline's word.

**4 — the extractor's refusals are tested.** Four cases in `tests/catalog.rs`, driven through
`ensure_tarball` because it takes any file and is the shortest path to `extract_runtime`. The
archives are written block by block with `common::payload::RawTar`, the way `tests/payload.rs`
writes its malicious ones: a packer that plays by the rules cannot lay down a symlink, a `..`
path, an absolute path or a device node, which is exactly why those four need writing by hand.
Each asserts the entry is named, the rule is stated, and no runtime directory is left in the
cache.

**5 — the release API is tested.** Five cases in `tests/otp_repack.rs` drive `repack_with` against
a `TestServer` through `Net { base_overrides: { GITHUB_API_BASE -> server.base() } }` — the
mechanism that existed for exactly this and had never been pointed at a fake API. The fake
release document writes its `browser_download_url` under `GITHUB_API_BASE` too, so one override
redirects both hops. The happy path pins the API's digest into `entry.upstream.sha256`; a digest
the body does not match is refused with both values; an asset with no `digest` is refused before
anything is fetched (`server.hits(ASSET_PATH) == 0`); a release holding another architecture's
asset names the file that was looked for; and a document with no `assets` array says so. Six more
in `tests/download.rs` cover `get_text` itself: the body verbatim under the GitHub accept header,
a 500 retried, a 404 asked exactly once, a body one byte over `MAX_TEXT_BYTES` refused rather than
read into memory, the offline refusal, and the base override.

**6 — the three sentences wrap with `\`.** And a shape test scans every string literal in `src/`
for a run of four or more spaces between two words, which is the check that found them; it carries
its own positive and negative case, so a scanner that stopped finding anything would fail rather
than pass.

**7 — both foreign-machine branches are tested.** `tests/regressions/` builds a runtime root
holding the running test binary with `e_machine` rewritten — `common::repack::patch_elf_machine`,
which C2 added for the same reason — so a machine with no cross toolchain has native code for
another architecture. The whole-tree case asserts a reported `Skipped` naming both machines rather
than a silent `NothingToStrip`, and the mixed case asserts the warning *and* that exactly one
candidate survived `natives.retain`, which holds whether or not `strip` is on the machine.

**8 — the remedy is a command that works.** `CatalogError::NotCached` carries a `command` built by
the new `catalog::fetch_command`, which appends the `--variant` the run was given and the
`--catalog` its origin came from (`CatalogOrigin::flag_path`, `Some` only for an explicit one —
the cached and embedded catalogues need no flag). The test does the only thing that cannot drift:
it parses the command out of the message, runs it as a subprocess, and asserts that `path` then
answers about the directory `fetch` filled.

**9 — one filler at a time.** `cache_lock` grew `wait_exclusive`, the waiting form of
`try_exclusive`: pruning treats a held lock as "leave this alone", and filling has to treat it as
"somebody is doing your work". Non-blocking `flock` retried inside `FILL_LOCK_BUDGET` (900 s,
because what holds it is a 40 MB download), never a blocking call in the kernel. `ensure_otp` and
`ensure_tarball` take it on `<cache>/otp/.locks/<entry>/.lock` — beside the entry, because the
entry directory does not exist until the rename that completes it — and re-check `is_complete`
after acquiring it, so the loser of a race finds the runtime rather than rebuilding it.

**10 — one variant namespace.** `config::OTP_VARIANTS` is `["default", "dynamic", "static"]`, the
catalogue's namespace rather than a linkage, and the refusal message is rendered from the constant
instead of spelling two of the three by hand. The test walks every `(target, variant)` pair
`catalog::upstream_asset` maps to an asset and asserts each one both parses in a `gleam.toml` and
is in the set — so the two namespaces cannot drift apart again without a failure.

**11 — `assert_hello` asserts what it claims.** `stdout.contains("hello") && contains('a') &&
contains('b')` is satisfied by the literal `args=` with every argument dropped. It is now
`contains("args=3 a b")` and `contains("hello from priv")`, the same two assertions
`scripts/smoke-matrix.sh` and `tests/e2e_hello.rs` make.

**12 — the two new helpers are documented.** `docs/dev/testing.md` gains a paragraph for
`tests/common/http.rs` — the three `Reply` shapes, the request log, port 0, `WAIT_BUDGET`, and the
fact that it has *no read timeout*, so a client that connects and never sends stalls the serving
thread — and one for `tests/common/catalog.rs`, including why `CatalogBuilder` deliberately does
not go through `Catalog::to_json`. `tests/smoke_matrix.rs` now pins both files and five of the
names in them, so the next helper without a paragraph fails the gate.

**13 — `OtpReq::Exact` says what it is.** The doc comment promised `otp_version = "29.0.5"` in a
`gleam.toml`; `TARGET_KEYS` has four keys and that is not one of them. Rather than add a
configuration key this milestone does not need, the comment now says what is true: nothing in a
manifest builds one, `bundle` always asks with `Host`, and this is the shape a pin will take —
and the shape the forward release warning is reachable through.

**14 — one spelling, one atomic write.** `write_otp_update` calls `catalog::has_scheme`, now
public, instead of `source.contains("://")`, and installs through the new `catalog::install`,
which writes `<destination>.tmp-<pid>` and renames. The race test runs a writer and a reader
against one path for sixty installs of a 385 KB document and parses every read; the path test uses
a directory whose name ends in a colon, which is the one shape the two spellings disagree about.

### 1 — a suggested command stopped being a command at the first space (low)

C3 gave `CatalogError::NotCached` a `command` field so that the remedy a user is handed carries
the flags the run that failed was given, and `catalog::fetch_command` builds it. It interpolated
every value with `{}`, the path through `Path::display`:

```rust
line.push_str(&format!(" --catalog {}", catalog.display()));
```

A catalogue under a directory whose name holds a space therefore rendered a line that is not the
command it looks like:

```text
error: .../otp/29.0.5-linux-x86_64-musl is not cached;
       run `ginary otp fetch --version 29.0.5 --target linux-x86_64-musl
            --catalog /home/u/my catalogs/dist/otp/catalog.json`
```

Pasted into a shell that is three arguments rather than two, and `ginary otp fetch` answers
`error: unexpected argument 'catalogs/dist/otp/catalog.json' found`. The remedy exists precisely
for the moment the user has already hit one obstacle; a second one, in the fix itself, is the
worst place to put it. A space is the ordinary case — `My Documents`, `Application Support` —
and a `;` or a `$(...)` in a path would be worse than a broken line.

RED first. `tests/regressions/c4_a_catalog_path_with_a_space_was_not_quoted.rs` builds a
catalogue with one real tarball under `<tmp>/my catalogs/dist/otp/`, runs
`ginary otp path --catalog <that>` for an entry that is not cached, and takes the command
out of the backticks of the refusal. It makes two claims, and both failed:

| test | claim |
| --- | --- |
| `the_remedy_quotes_a_catalog_path_that_holds_a_space` | the path is not pasted bare, and appears as one quoted argument |
| `the_remedy_a_space_in_the_path_earns_still_runs_in_a_shell` | the line, handed verbatim to `/bin/sh -c`, fills the cache the run was refused for — and `ginary otp path` then answers |

The second is the assertion that cannot drift: it does not check a spelling, it runs the sentence.
`ginary` reaches the shell's `PATH` as a symlink to this test run's own binary in a directory the
test owns, with `env_clear()` around it, so nothing ambient can make the line work.

The fix is a helper rather than a format string. `process::shell_quote` renders one word so that a
POSIX shell reads it back as exactly that string: a word of nothing but letters, digits and
`._-/=:,+@%` is returned borrowed, because quoting `29.0.5` would only make the line harder to
read, and anything else is wrapped in single quotes — inside which a shell expands nothing at all
— with the one character that cannot appear there written as `'\''`, close, escape one, reopen.
An empty word quotes to `''`. `process::shell_quote_path` is the same over a `Path`, lossily for
one that is not UTF-8, which is how every other message in this crate renders a path.

It lives in `src/process.rs` because that is where this crate's knowledge of running programs
already is, and because C4's own hook execution runs `sh -c`. `catalog::fetch_command` now sends
all four of its values through it — the version, the target, the variant and the catalogue — so
the only renderer that builds a command out of user-supplied values has one rule rather than four
interpolations.

`shell_quote` is unit-tested beside the code in `src/process.rs`: the words it leaves alone (and
that it really borrows rather than copies them), a space, the eight metacharacter shapes it wraps,
the single quote, the empty word, both `shell_quote_path` branches, and — the test that makes the
rest more than an opinion — a real `/bin/sh` that prints eight quoted words back and has to
produce the original string each time.

### Three decisions the spec left to the implementation

**A warning belongs to the row it is about.** `scan_shipment` returns `Vec<NativeArtifact>` as
specified, and the artifact carries `warning: Option<String>`, so a file that begins like an
object and will not parse is a row with `NativeKind::Unknown` *and* the sentence saying why. A
list of warnings beside the list of artifacts would have to be matched up by hand.

**`reconcile` answers with a `Reconciliation`, not a bare `Vec<Replacement>`.** The
`--allow-native-mismatch` path is *defined* by the sentence it prints, and a caller that had to
reconstruct that sentence from the artifacts would print a different one.

**Its arguments travel in a `ReconcileCtx`.** The spec's positional list is eight values, three of
them only used to run a hook; a struct is what stops a caller swapping two paths silently. The
hook needs the ERTS version as well as the runtime root, because `ERTS_INCLUDE_DIR` is
`<root>/erts-<vsn>/include` and globbing for it would be a second answer to a question the build
already has.

## GREEN

Every RED stub replaced, every `// RED: replaced in GREEN` marker gone, and
`NativeError::NotImplemented` deleted rather than left unreachable — a placeholder that compiles
is a placeholder somebody ships.

### What was implemented

**`src/native.rs`** — the whole module, in three layers.

`describe_object(path)` is the layer the other two are written on: it stats the file, reads its
first 64 bytes, and answers `None` for anything that begins like no object at all. ELF goes
through `elf::inspect_bytes`, because a Linux object's target is its `PT_INTERP` and only
`ElfInfo` carries one; PE and Mach-O go through `object::read::File::parse`, which is where their
machine and their `Dynamic`/`Executable` kind come from. A `MZ` with no `PE\0\0` behind it is a
DOS program and not an object. A file over `MAX_OBJECT_BYTES` is described as `Unknown` with a
reason rather than read into memory, which is the bound `verify` and `doctor` already apply. The
Cargo `object` dependency gained its `macho` feature for this, and the comment above it says why.

`scan_shipment` walks each application's `priv` and nothing else, sorted, depth-bounded, never
descending a directory symlink and following one only to a regular file — the rule `doctor`'s own
walk follows. Every unreadable directory is an error rather than a skip: a shipment ginary cannot
walk is a build that has to stop, because an object nobody looked at is what this module exists to
refuse.

`reconcile` applies the four rules in the spec's order, collects the mismatches, sorts them by
path, and raises one table. The static-runtime check runs after the loop over the artifacts the
build will actually carry, so a NIF an override answered for still counts. `run_hook` substitutes
the two tokens, creates the output directory, and runs the line through `/bin/sh -c` in the
project root with the six variables — `ERL_INTERFACE_INCLUDE_DIR` present only when the runtime
really has one. `apply` writes the replacement's bytes *into* the staged file rather than copying
over it, so the mode assembly gave it survives a vendored file that is `chmod 644`.

**`src/process.rs`** — `run_env_in_dir_with_timeout`, which the two existing runners now delegate
to. The variables are *added* to this process' environment rather than replacing it: a build hook
is a developer's own command line and needs the `PATH` that finds its compiler.

**`src/config.rs`** — `NativeConfig` and `ToolsConfig::native`, so `[tools.ginary.native.<pkg>]
build` parses under `deny_unknown_fields`; `native_hooks()` reads it back as the map
`TargetNativeCfg` is written in terms of. `BuildFlags` and `BuildOptions` gained
`allow_native_mismatch`, and `BuildOptions` gained the hooks. There is deliberately no
`gleam.toml` key for the flag.

**`src/bundle.rs`** — the shipment is scanned once for the whole build, whatever the target, and
the scan's warnings go into the report unattributed because they are facts about the shipment
every target shares. Per target, between staging and stripping: `reconcile` with that target's
overrides, the project's hooks and that runtime's own `nif_loading`, then `apply`. The manifest's
`native` list is read back off the staged tree *after* stripping, so every row is what the payload
carries; an application the closure did not stage has no row.

**`src/doctor.rs`** — `ProjectReport::targets` and one column per target in the native table,
through a width the const-generic renderer cannot express (`render_wide_table`, cell-for-cell the
same layout). Whether a target can load a NIF is read off `otp_variant` rather than off a runtime,
because `doctor` resolves none.

**`src/verify.rs`** — `native_issues` cross-checks every `manifest.native` row against the index
and against the machine of the object the payload streamed.

**`src/cli.rs`** — `--allow-native-mismatch` on `build`, documented in its help as the flag the
refusal names and as the one that does not lift the static-runtime refusal.

### Two things the spec asked for that were already there

**The strip rule.** "A cross-architecture object is not stripped by host binutils, and the report
says so" is C3's rule, in `strip.rs`, held by
`tests/regressions/c3_a_foreign_native_left_the_strip_report_silent.rs`. A replacement applied
*before* stripping therefore needs no new rule and got none; what C4 added is the ordering that
puts it in front of the phase that already knows what to do with it, and the module documentation
now says so.

**`ObjectFormat` beside `manifest::NativeKind`.** They are two enumerations answering different
questions — what a build reads, and a wire value `docs/format.md` fixes — and `bundle` maps one
onto the other in one `const fn`.

### GREEN / test corrections

One test was corrected, and the reason is a rule the milestone itself fixes.

**`tests/e2e_native.rs::allowing_the_mismatch_builds_the_artifact_and_says_what_it_did`** built
for `linux-aarch64-musl` with the host's own binary planted under `priv`, passed
`--allow-native-mismatch`, and asserted the build *succeeds*. It cannot, and the reason is the
sibling test two lines below it: the committed catalogue publishes `linux-aarch64-musl` as the
`static` variant only, a statically linked emulator has `nif_loading: false`, and a shared object
in that artifact is the one refusal `--allow-native-mismatch` deliberately does not lift. The two
tests together asserted that the same flag both does and does not waive `StaticRuntime`.

The claim worth keeping is "a build whose only fault is a mismatch is allowed through and says so",
so the test now builds for `linux-x86_64-gnu` — whose catalogue runtime is dynamic — with the
object planted for *aarch64* through `patch_elf_machine`. That is a genuine mismatch, waived by
the flag, on a runtime that could load a NIF; the assertions are unchanged. A comment in the test
records why the target is a gnu one.

Nothing else was touched. In particular `doctor::a_real_elf_under_priv_is_listed_with_what_it_is`
expects no verdicts for a project with no `[tools.ginary]` table, and that is now the implemented
rule rather than a correction: `ProjectReport::targets` is what the table *names*, read with a
second tolerant parse of the same text, and a project that has never mentioned a target gets no
column. `[tools.ginary] targets` defaults to `host` inside `ProjectConfig` precisely so that a
build always has one; a `doctor` table that inherited that default would print a column nobody
asked for.

`catalog::DEFAULT_MUSL_VARIANT`, the static build — which is why the ordinary cross-compiling

be silently mis-described. The one case this cannot answer is a `dir:` or `tarball:` runtime that
happens to be static — nothing but the emulator's own header says so, and reading it is half of a
build — and there the build has the last word and says it.

`NativeKind::as_str`, the same words as before for the two kinds that print. An ELF's raw
`e_type` is still reported where it is the subject, by `ginary inspect`.

**3 — refuse before the loop.** The static-runtime rows are computed from the scan and the
runtime, and no rule in the loop can change them: a NIF an override or a hook answered for is
still a NIF. The block moved above the per-artifact loop, with the comment saying why it is not
merely an optimisation — deciding it afterwards spends one `HOOK_TIMEOUT` per configured package,
the project's own compiler, on output thrown away one line later.

**4 — one shell on every host.** The `cfg(windows)` alternative is gone: `HOOK_SHELL` is
`/bin/sh` and `HOOK_SHELL_FLAG` is `-c` wherever ginary runs. A hook compiles native code for a
Linux target and wants a POSIX toolchain anyway, and a machine with no `/bin/sh` gets
`NativeError::HookProcess` naming it rather than a command line a different shell would read
differently. `process::shell_quote`'s own contract is true again.

project has a shipment at all, because reporting that a directory nobody ever created could not be
read would be a note about nothing.

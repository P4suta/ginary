# A0 — Scaffolding

Date: 2026-08-30 · Status: complete

## Scope

Phase A0 of the v1 plan: create the repository, the crate, the developer tooling skeleton and
the documentation set, and implement the two commands that the scaffolding itself needs —
`ginary version` and `ginary doctor`. `ginary build` is explicitly *not* implemented and does
not appear as a subcommand: the plan forbids placeholder exports.

`src/target.rs` is the plan's C1 type, seeded here because both `version` and `doctor` have to
report a host target string.

## GREEN

One bug was found by a test during GREEN, which is the point of writing them first.

`doctor::run_with_timeout` drains the child's stdout and stderr on two threads so a chatty child
cannot deadlock on a full pipe. The first implementation joined those threads *before* killing a
child that had overrun its budget. The reader threads block until the pipes close, and the pipes
stay open for as long as the child lives, so the timeout path waited out exactly the hang it had
just detected. `a_hanging_probe_times_out_and_is_killed` caught it — a 200 ms budget took over
60 seconds:

```
thread 'doctor::tests::a_hanging_probe_times_out_and_is_killed' panicked at src/doctor.rs:511:9:
the timeout must not wait for the child
```

The fix kills and reaps first and leaves the reader threads detached, since they end when the
pipes finally close. The test asserts on elapsed time, not just on the error variant, so the
regression cannot come back silently.

## Open issues

1. **MSRV is declared but unverified.** `rust-version = "1.88"` and CI pins `1.88.0`, but the
   development machine only has 1.97.1, so the first CI run is the first real MSRV check. If a
   transitive dependency raises its own MSRV, `--locked` plus `Cargo.lock` is the lever.
2. **`GINARY_REQUIRE_TOOLCHAIN` is a convention with no code yet.** No test needs a toolchain
   in A0, so `require_tools` does not exist. It arrives with the first gated test in A1.
3. **`cargo deny` cannot run here.** `deny.toml` is committed (copied from release-glz; its
   `[graph] targets` list was corrected in fix round 1 to the seven triples of `target::ALL`)
   but `cargo-deny` is not installed and there is no CI job for it yet.
4. **`run_with_timeout` leaves reader threads detached on timeout.** Deliberate, and harmless
   for a short-lived `doctor`, but it must not be reused verbatim on the launcher path.
5. **Cache directory resolution is host-uniform.** The plan's `~/Library/Caches/ginary` on
   macOS and `%LOCALAPPDATA%\ginary` on Windows, and the `$TMPDIR/ginary-<uid>` fallback, are
   not implemented; A0 implements exactly the three documented rules. `docs/format.md` and ADR
   0005 record the intended end state.
6. **`docs/format.md` specifies more than exists.** The trailer, manifest and index are
   specified in full but nothing reads or writes them yet; that is A3.
7. **`mise run check` installs nothing.** `[tools]` pins `gleam = "1.18.1"` and
   `erlang = "29.0.5"`, which mise resolved against the versions already present rather than
   building OTP from source. A machine without them will pay for a kerl build on first use.
8. **`mise run smoke` and `mise run package` are declarations, not tasks.** Both are listed by
   the plan among the A0 tasks, and both need an artifact that does not exist yet. They are
   defined and exit 1 with the command they will run: `package` becomes `ginary build` over
   `tests/fixtures/hello_ginary` in A4, `smoke` becomes `scripts/smoke.sh` in A5.

## Fix round 1

Date: 2026-08-30 · Ten findings from the A0 adversarial review, all addressed.

Behavioural findings were fixed test-first: the regression test was written and run, its failure
observed and recorded below, and only then was the code changed.

### 1 (high) — `cargo test` flaked with `ETXTBSY`

`src/doctor.rs`'s `script()` test helper wrote an executable and exec'd it straight away. Cargo
runs tests as threads of one process, so while one thread held the write descriptor on the new
file, a sibling thread's `Command::spawn` could sit between `fork` and `exec` holding an
inherited duplicate of it, and any exec of that inode in the window returned `ETXTBSY`. The
review measured two failures in twenty-six runs.

RED: `scripts_written_and_run_in_parallel_are_never_text_file_busy` creates and runs 200 scripts
across eight threads. It made the race fire on the first attempt — not in itself, but in a
sibling test, which is exactly how the review saw it:

```
---- doctor::tests::a_hanging_probe_times_out_and_is_killed stdout ----
thread 'doctor::tests::a_hanging_probe_times_out_and_is_killed' panicked at src/doctor.rs:517:9:
cannot run `/tmp/.tmphgvAb5/prog`: Text file busy (os error 26)
```

GREEN: the fix is in the test helper, not in production — `run_with_timeout` must keep reporting
`ETXTBSY` rather than papering over it. Every script now starts with a
`case "$1" in --ginary-exec-probe) exit 0;; esac` guard, and `script()` does not return until
`wait_until_executable()` has actually exec'd the file once. The retry cannot loop forever: the
only descriptor on the inode belongs to `fs::write`, which has already returned, so once an exec
succeeds no new writer can appear.

Afterwards: `cargo test --lib` green, then the compiled test binary run 25 more times at
`--test-threads 8`, 0 failures. The gate table below is corrected.

### 2 (medium) — the `erl` probe could drop a crash dump in the working directory

RED: `the_erl_probe_cannot_drop_a_crash_dump_in_the_working_directory` failed on "the erl probe
sets an emulator environment variable". GREEN: the probe's argument list now carries
`-env ERL_CRASH_DUMP <null device>`, as the plan's A2 `erl` invocation does, with `NULL_DEVICE`
selected per platform. The guard is asserted by position, so it cannot be dropped later.

### 3 (medium) — unit tests shelled out to the real toolchain

Three unit tests called `Report::gather()`, which runs `gleam`, `erl`, `strip` and `docker` from
the ambient `PATH`, against ADR 0006's rule and against `docs/dev/testing.md`'s claim about
`test:fast`.

`Report::gather_from(probes, path_var, env)` is now the pure half and `gather()` the thin wrapper
that supplies `PROBES`, `PATH` and `EnvSnapshot::from_env()`. `cli::dispatch` gained
`write_version` and `write_doctor`, which render a report they are handed. The three tests were
replaced by five that inject a temporary `PATH` of fake scripts and a fixed `EnvSnapshot`:
`gathering_probes_the_given_path_and_never_needs_rustc`,
`gathering_takes_the_cache_directory_from_the_snapshot`,
`gathering_records_why_the_cache_directory_is_unresolved`, and the two `cli` tests now build a
sample report. `gather()` keeps its end-to-end coverage in `tests/smoke_cli.rs`.

### 4 (medium) — `run_with_timeout` leaked a child on the `try_wait` error path

The timeout path killed and reaped; the `Err(source)` arm returned without doing either. Rather
than repeat the obligation at each `return`, the child is now owned by a `ChildGuard` whose
`Drop` kills and reaps, so no future error path can forget it. The `try_wait` failure itself
cannot be induced without fault injection, so the anchor test is on the guard:
`dropping_the_child_guard_kills_and_reaps_the_child` starts a script that appends to a file every
20 ms, drops the guard, asserts the file stops growing (killed) and that `/proc/<pid>` is gone
(reaped). Verified as a real detector by breaking `Drop` on purpose and watching it fail.

### 5 (low) — `test:fast` and the missing `smoke` / `package` tasks

`test:fast` is now `cargo test --lib --bins --test smoke_cli`: with finding 3 fixed, that is
exactly the set of tests needing no toolchain. `smoke` and `package` are declared and fail with
the command they will run and the milestone they arrive in; open issue 8 above records the
deferral.

### 6 (low) — `cargo deny` checked one target out of seven

`[graph] targets` now lists exactly the seven triples `Target::rust_triple()` returns for
`target::ALL`, with `x86_64-pc-windows-gnu` rather than the msvc triple. RED:
`cargo_deny_checks_every_target_ginary_models` parses `deny.toml` at compile time through
`include_str!` and compares the two lists, failing with `left: ["x86_64-unknown-linux-gnu"]`
against the seven expected. The two lists can no longer drift apart silently.

### 7 (low) — SECURITY.md described unbuilt behaviour as fact

The threat model keeps its bullets but is now prefaced by a paragraph in `debugging.md`'s style
stating that none of the properties is implemented yet and pointing at this log.

### 8 (low) — dead serde derives and unreachable match arms in `target.rs`

`Serialize`/`Deserialize` are gone from `Os`, `Arch` and `Libc`; all `Target` serde goes through
the canonical name, so they were never exercised. `rust_triple()` stays total, but the
`(Os::Windows, Arch::Aarch64, _)` arm is now commented as being outside `ALL` and unreachable
through `FromStr`, and `rust_triples_match_the_documented_mapping` pins all seven mappings as
strings instead of only asserting they are distinct.

### 9 (low) — ADR 0005 read as in force, and there was no ADR index

ADR 0005 keeps its decision and gains an `Implementation` paragraph in `Consequences` naming what
is built (the three location rules in `src/cache_dir.rs`) and what is not (platform bases, the
`$TMPDIR` fallback, the extraction protocol, `preflight`, `.lock`) and where each lands.
`docs/adr/README.md` now lists all six records, as beamtrace does.

### 10 (low) — doc-comment and wrapping nits

`script()`'s doc says it returns the script's path. The one re-wrappable prose line in ADR 0005
was re-wrapped. `CONTRIBUTING.md` now records that Markdown table rows and unbreakable string
literals are exempt from the 100-column rule, so the remaining long lines are not re-raised: they
are all table rows in `debugging.md` and `testing.md`, the row for `src/cache_dir.rs` in this
file, and the `-eval` literal in `src/doctor.rs`.

## Fix round 2

Date: 2026-08-30 · Three findings from the second A0 review (one medium, two low), all addressed.

Same rule as round 1: the behavioural finding was fixed test-first, and the observed failure is
recorded below.

### 1 (medium) — `PROBE_TIMEOUT` did not bound `run_with_timeout` on the success path

Once the direct child was reaped, the function called `stdout.join()`. The reader thread is
blocked in `read_to_end`, which returns only when *every* write end of the pipe is closed —
including the duplicate a grandchild inherited. A probe that backgrounds a helper therefore held
`doctor` for as long as the helper lived, with no `ProbeError::Timeout` and no diagnostic.

RED first: `a_grandchild_holding_the_pipes_cannot_outlast_the_timeout` runs a script of the shape
`sleep 10 & echo gleam 1.2.3` with a 200 ms budget and asserts the call returns inside five
seconds. It failed with `waited 30.002547888s on a 200ms budget` against the earlier `sleep 30`
form of the script, which is the reviewer's measurement reproduced inside the suite.

The readers are no longer joined at all. `drain` now returns a `Drain`: the thread appends each
chunk to an `Arc<Mutex<Vec<u8>>>` and signals a channel at end of file, and `Drain::take_until`
waits on that channel with `recv_timeout` before copying whatever has been published. The
deadline it is given is `deadline.max(now + DRAIN_GRACE)`, `DRAIN_GRACE` being 500 ms: exiting
closes the child's own pipe ends, so an unencumbered reader finishes at once and the grace is
slack for scheduling, not a second budget. A reader still blocked at the deadline is abandoned
exactly as the timeout path already abandoned it, and its partial output is returned — which the
test also asserts, since `1.2.3` was written before the deadline and must still be reported.
Standard error keeps its reader (a full stderr pipe would still block a chatty child) but is
never read back.

The docs now state the narrower truth: the timeout bounds the whole call, and on the timeout path
only the direct child is killed — ginary does not put probes in a process group, so a grandchild
survives. `Report::gather`'s doc says the bound covers reading the output, not only the wait.

### 2 (low) — `docs/dev/testing.md` contradicted itself about `test:fast`

The file called `test:fast` the subset that spawns nothing external and then, two paragraphs
later, said `tests/smoke_cli.rs` drives the real binary — which runs the real `doctor` against the
ambient `PATH`. `--test smoke_cli` stays in the task: nothing there *requires* a toolchain, which
is what the task name claims. The paragraph now separates the two halves — library and binary
targets spawn only fake scripts in temporary directories, `smoke_cli` probes whatever is on
`PATH` without needing any of it to be present or to succeed — and names `PROBE_TIMEOUT` as the
bound on what a hung tool can cost. The comment above the task in `mise.toml:29` says the same in
two lines and points at the document.

### 3 (low) — a `try_wait` failure was reported as `ProbeError::Spawn`

`ProbeError::Wait { program, source }` is new, with the message `cannot wait for `{program}`:
{source}`, and the `try_wait` arm returns it. The old label told the user a program that is
running could not be started. The arm needs fault injection to reach, so
`a_wait_failure_does_not_claim_the_program_could_not_be_run` pins the two variants' `Display`
strings apart instead.

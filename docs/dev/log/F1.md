## Implemented user paths

- Artifact, manifest and SBOM paths are planned before export, including symlink traversal,
  existing hard links, implicit cross stubs, source trees and selected runtime caches. Same-project
  builds hold a project lock through finalization; different projects have independent locks.
  Each invocation and target owns a unique staging tree. Detailed library failures and CLI JSON
  version 2 retain completed artifacts, the failing target, unattempted targets and cleanup evidence.
- Every requested target gets an SBOM. Atomic document/executable publication preserves old bytes
  on injected partial-write or replacement failure. The macOS path independently checks the final
  signature and payload before publication and reports the measured signed size. Real CLI fault
  tests cover a failed manifest after its executable was already completed, and a successful retry.
- Clean, uninstall and automatic pruning require attributable ownership and retain live extraction,
  locked entries, crash evidence and unrelated files with reasons. Selftest uses the normal launch
  environment handling and holds the runtime cache lock while the child runs.
- Verification checks object format against OS as well as CPU, archive/index duplication and
  conflicting destinations. Target filename rules are independent of the reader's OS; extraction
  refuses names a foreign host would reinterpret. Payload-integrity failure identifies the deep
  verification it prevented instead of claiming zero problems. Detailed library results and
  CLI JSON distinguish `passed`, `failed`, `not_run` and `incomplete` stages. Unreadable input
  still yields JSON; a valid digest over malformed archive contents is explicitly incomplete.
  Diagnose retains those stage outcomes and leaves unknown finding counts null.
- Process reports retain bounded stream tails, omitted byte counts, elapsed time, status and
  cleanup evidence. Version-2 traces correlate runs and operations, serialize independent file
  appenders, redact sensitive values and report sink failures without failing the application.
  Existing non-trace files cannot be turned into logs by a mistaken diagnostic path.
- Doctor distinguishes missing, unstartable, timed-out, nonzero, invalid and incompletely captured
  tool probes. Diagnose collects environment readiness, artifact verification, trace statistics and
  crash statistics into local text and JSON without executing the supplied artifact or copying
  raw sensitive values.
- Native installed OTP roots can be repacked on Windows/macOS. Distribution assembly validates all
  seven target fragments, binary flavors, runtime digests and sizes, then verifies staged bytes.
  Publication reserves a fresh output directory without replacement and writes the checksum marker
  last, retaining verified staging if publication fails. Hosted publication is explicit and its
  retry/failure tests run solely against local mocks.
- Mutation discovery preserves every candidate and assigns it to an applicable native OS.
  The final gate reconciles the complete plan with raw phases, diffs, logs and process records;
  an empty tail shard, a missing job and a completed test have separate meanings. Independent
  parser and fault-injection tests cover the gate itself. See [native mutation gates](F1-mutation-platforms.md).

## Defects found during the acceptance review

- Windows normalizes ordinary output names ending in a dot or space. Two absent names could
  pass identity checking and later publish the SBOM over the executable. An actual filesystem
  reproduction preserved the failure in `alias-review.log`; destination validation now rejects
  ambiguous Windows components before opening a handle or writing a temporary file. Independent
  output-module regression execution passes 9 tests (`windows-alias-green.log`).
- Verification-stage regressions first failed for missing JSON outcomes and unreadable-input
  output. The subsequent diagnose review also proved that a damaged artifact could still render
  zero findings. The corrected verification/diagnosis regressions pass 11 tests, including a
  damaged archive with a recomputed, valid outer digest (`diagnosis-stages-{red,green}.log`).
- Actual actionlint found an upstream Windows pipe deadlock while passing a long inline script
  to ShellCheck. Extracting that script, linting its file directly and bounding the regression
  preserves all lint rules. All seven workflow files and the macOS helper pass the real tools;
  [the reproducer and cause](F1-actionlint-pipe.md) are recorded separately.
- The coverage gate accepted malformed, truncated and inconsistent LCOV totals. It now rejects
  invalid selected counters, unfinished records and invalid percentage floors. Fifteen local
  shell cases pass without lowering the line or branch floors (`coverage-gate/green.json`).
- Doctor's predictable execution probe could overwrite and then delete a pre-existing user
  file. A native CLI reproduction demonstrated the loss; exclusive temporary-file creation
  now preserves existing files and hard links. The successful native reproduction retains
  both `evidence.json` and `verification.json` under
  `doctor-collision-2040ea27086648f7a881f5400ede390c/`.
- Concurrent library extractions used one PID-based work directory and a shared archive cursor.
  Each invocation now owns an exclusive temporary directory and reads explicit archive offsets.
  Three portable concurrency regressions, thirteen maintenance regressions and one paused
  extraction/cleanup/recovery process test pass. Existing cache tests have twenty-eight
  executed passes and two explicit missing-`flock` skips (`cache-validation.json`).
- Repacking the real Windows OTP installation first failed with OS error 206: the BEAM
  stripper exceeded Windows' command-line limit. Batches now account for quoted UTF-16
  command length before spawning. The three minimized regressions include stripping four
  hundred modules with real Erlang (`beam-validation.json`). A full repack subsequently
  succeeded in 674.6 seconds, stripping 1,322 modules and producing a 46,202,598-byte runtime
  whose independently measured digest matches its catalog (`native-otp-repack-rerun/`).
- The same real consumption path proved that `otp fetch` incorrectly rejected adjacent local
  archives while offline. Three CLI regressions reproduced the failure; limiting that early
  refusal to remote URLs lets the existing digest-checked local importer run. All sixteen OTP
  CLI tests pass, including relative/absolute local paths, wrong digests and remote refusal
  (`offline-local-catalog-{assertions-red,green}.log`).
- Coverage exposed an additional library ownership gap in `assemble::stage`: successful and
  failed calls both removed a pre-existing PID-named directory. The two actual failures are
  retained in `stage-ownership-red.log`. Staging now acquires its own temporary directory, and
  cleanup failures preserve the original error, cleanup cause and residue path through the
  additive `StageCleanupError`, without adding variants to the existing public error enum.
  An independent publication test also demonstrated that Windows `std::fs::rename` replaces
  an existing empty directory. The Windows adapter uses no-replacement `MoveFileExW`; Unix
  targets use their corresponding no-replacement rename. Subsequent validation is recorded
  independently rather than treating the first attempted fix as successful.
- The first Linux compile exposed a missing Unix-only `Instant` import in the process tests.
  The import is restored inside the test module; the initial compile failure and subsequent
  instrumented run are retained separately. Windows then completed its plain and stub runs
  with one shared dependency-documentation regression: the new `renameat_with` call was absent
  from the enumerated dependency contract. Both the Unix dependency comment and its exhaustive
  call table now include it; the failed full-run records are preserved for the corrected rerun.
- The first actual fuzz build resolved a stale dedicated `fuzz/Cargo.lock` rather than using
  the current library's dependency set. The refreshed lock was checked against the parent
  runtime dependency names, registry sources and checksums; the only extra packages are the
  fuzz workspace, `libfuzzer-sys` and `arbitrary`. Since cargo-fuzz 0.13.2 does not expose
  `--locked`, the nightly workflow and local mise tasks run locked Cargo metadata first.
  An actual isolated offline check refuses the previous lock with exit 101 and accepts the
  refreshed lock with exit 0, leaving both files unchanged. Evidence is
  `.cache/assurance/F1/linux-fuzz-rerun/{lock-verification,metadata-verification}.json`.

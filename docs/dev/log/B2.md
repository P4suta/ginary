### 1 — the documented fault-point lists were behind `src/fault.rs` (low)

`docs/dev/debugging.md` and `docs/dev/testing.md` both enumerate the `GINARY_FAULT` points and
both claim to be complete. Neither listed `before-lock`, which B1 added along with the preflight
retry, and `testing.md` was also missing `pack:fail` from A4 — so the two documents disagreed
with the code and with each other, and a reader arming a point from either list would not have
found the one that exercises the prune/lock race.

Correcting the prose alone would have left the same failure mode in place for the next point, so
the lists are now held against the code:

- `src/fault.rs` gains `pub const FAULT_POINTS: [&str; 6]`, the six points in the order the
  module's own table gives them. It is the single list the others are checked against.
- Four unit tests in `src/fault.rs` close both directions of drift.
  `every_call_site_is_a_listed_point` scans every `src/*.rs` except `fault.rs` for
  `fault::point("…")` and fails on a name the table does not carry; `every_listed_point_has_a_call_site` fails on a listed point nothing arms, so a
  removed point cannot survive in the documentation as a fault no test can trigger;
  `both_documents_list_every_point` requires each point to appear as inline code in both
  documents, matching a bare `` `before-lock` `` as well as `` `after-extract:pause` `` so a
  point whose action is `on` reads naturally in prose; and
  `no_document_lists_a_point_this_build_does_not_have` treats any backticked `<point>:<action>`
  whose action is in `ACTIONS` as an enumeration entry and requires its point to be known, which
  is what catches a renamed point left behind in the text.
- `docs/dev/debugging.md` adds `before-lock` to the `GINARY_FAULT` row with its effect (the cache
  entry removed between the preflight and the shared lock, which is what a prune that won the
  race leaves behind).
- `docs/dev/testing.md` adds both `before-lock` and `pack:fail`, moves the "first three are about
  timing" count to four now that `before-lock` joins them, splits out `pack:fail` as the one
  build-side point, and points at `FAULT_POINTS` as the list the document is held against.

Each new test was watched fail before it was accepted: removing the `before-lock` clause from
`docs/dev/debugging.md` makes `both_documents_list_every_point` report
``docs/dev/debugging.md` does not list the `before-lock` fault point``, and the clause was
restored afterwards.

### The stubs the tests compile against

A compile error is not RED, so `src/verify.rs`, `src/sbom.rs` and `src/crashdump.rs` exist with
their whole public API declared and every body a stub marked `// RED: replaced in GREEN`. The
stubs are honest rather than `todo!()`: a function that answers a question returns the empty
answer (`String::new()`, `None`, `false`, a document with no packages) and a function that does
work returns `Err(<Error>::NotImplemented)`. Each of the three error enums carries exactly one
such variant, and each is marked in the source; removing it is part of GREEN, and no other
production code path can reach it.

### Test helpers and fixtures

**`tests/common/repack.rs`** is the one new helper and the reason the four index findings are
testable at all. `SyntheticArtifact` builds its payload through the real
`ginary::payload::pack`, which computes `ginary.index.json` from the very tree it packs, so an
index that disagrees with the payload cannot be produced by the code that writes both from one
walk. `repack::build` lays the archive out entry by entry instead: it stages the same tree,
builds the same index, and *then* rewrites a file's bytes, deletes a row, or adds a row for a
file nobody packed. The trailer it appends is a real digest over the payload it actually wrote,
which is the point — the payload hash matches, and the artifact is still wrong. It also carries
`with_native_object`, which copies this test run's own binary in at
`lib/hello/priv/bin/tool`, and `patch_elf_machine`, which rewrites the two bytes of `e_machine`
so a test on one architecture can produce a binary for another with no cross toolchain.

**`tests/fixtures/crashdump/`** holds `synthetic.dump`, `truncated.dump` and a `README.md`
recording what each is for. The synthetic dump is hand-written, its shape copied from a real
OTP 29 dump: seven `=proc:` sections rather than five so "the top five" is a claim, three of
them unnamed because an unregistered process is the common case, and the largest heap in the
middle of the file so a reader that took the first five in file order fails.
`truncated.dump` is its first 780 bytes, which lands inside a `=proc:` section.

**The recipe for a real dump**, verified during this phase and used by the gated
`a_dump_a_real_runtime_wrote_is_summarised`:

```console
erl -noshell -env ERL_CRASH_DUMP <tmp>/dump \
    -eval 'spawn(fun() -> exit(kaboom) end), timer:sleep(100),
           erlang:halt("kaboom", [{flush,true}]).'
```

It exits 1, prints `Crash dump is being written to: <tmp>/dump...done`, and leaves a 1.8 MB
dump whose first five lines are `=erl_crash_dump:0.5`, the unlabelled date, `Slogan: kaboom`,
`System version: Erlang/OTP 29 [erts-17.0.5] …` and `Taints: `, and whose last line is `=end`.
`erlang:halt(abort)` was not used: it dumps core and writes no crash dump at all. `=end` is
what `CrashDump::truncated` is derived from — a dump that does not carry it stopped early.

### `src/crashdump.rs`

A line reader over a `BufRead` and a small state machine. Two bounds are the design rather than
defensive extras, because the file it reads is routinely larger than the machine reading it:

- **A line is never held whole.** `Lines::next_line` fills a buffer capped at `MAX_LINE_BYTES`
  plus a private `MAX_KEY_BYTES` and consumes the rest of the line without keeping it, and every
  extracted value is then cut to `MAX_LINE_BYTES` on a character boundary. The key margin is why
  the cap is stated as a bound on the *value*: a `Slogan: ` in front of it must not eat into the
  64 KB the reader promises to keep, and the doc comment on `MAX_LINE_BYTES` was reworded from
  "the longest single line" to "the longest value" to say so.
- **The top processes are a running list, not a sort.** `flush` offers each `=proc:` section to a
  `Vec` that never grows past `TOP_PROCESSES`, inserting at the first position whose heap it
  beats, so equal heaps keep file order and a dump with a million processes costs what a dump
  with ten costs.

The header keys are read only before the first `=section`. A `=proc:` section has a `Name:` of
its own, and a reader that matched header keys anywhere would take the last process's name for
the runtime's slogan; `a_process_key_is_never_read_as_a_header_key` is the unit test for it.
`truncated` is derived from the last non-empty line not being `=end`.

Nine unit tests were added beside the ten integration tests, for the shapes a fixture cannot
carry: an empty file, a dump with no second line, a heap that is not a number, fifty processes,
three of one size, a last line with no terminator, CRLF, and an empty `Taints:`.

### `src/verify.rs`

`verify_with` opens the artifact, takes the payload digest through `inspect::verify`, and then
streams the payload a second time. Per entry, `read_entry` reads the first four bytes, decides
from the ELF magic whether to keep the rest, and hashes everything either way; the entry's index
row is removed from a `BTreeMap` as it is accounted for, so what is left at the end is
`IndexMissing`. Issues are sorted by path and then by the order the variants are declared.

Three decisions are recorded in ADR [0011](../adr/0011-verify-and-sbom.md), and two of them came
out of the tests rather than out of the plan.

**The loader prefix rule is conditional on the allowlist.** `the_allowlist_is_the_documented_set`
requires `needed_is_allowed("ld-linux-x86-64.so.2", &NEEDED_ALLOWLIST)` to be true, and
`a_needed_outside_the_allowlist_is_reported` — which injects an *empty* allowlist as the test
seam — requires every `DT_NEEDED` of a real binary to be reported, the loader included. An
unconditional `starts_with(LOADER_PREFIX)` satisfies the first and fails the second, which is
what the first GREEN run showed. The rule that satisfies both is a real one: the loader *is*
glibc, so it is allowed exactly when the allowlist names `LOADER_COMPANION` (`libc.so.6`). An
empty allowlist then means what it says, which is what makes the seam a seam.

**A payload that does not match the trailer is not read further.** `verify` on a
`SyntheticArtifact` whose tail has been broken must still return a report — the test is
`a_payload_that_no_longer_matches_the_trailer_is_not_ok` — and the second pass over those bytes
fails in zstd with `Data corruption detected` before any entry comes out. So `verify_with`
returns after the digest when the digest does not match: every entry past the damage is bytes
nobody wrote, and a table of findings about them would describe the damage rather than the
artifact.

**A fifth issue kind.** `Issue::UnreadableObject` was added for a payload entry that begins with
the ELF magic and either does not parse or is larger than `MAX_OBJECT_BYTES`. The spec names
four kinds; the house rule that skipping is a reported decision and never a default leaves
nowhere else for that outcome to go, and no test produces it. It is recorded in the ADR.

`src/cli.rs` needed one correction: `write_sbom_for` passed `document.name` to `sbom::out_path`,
which is `<app>-<version>`, and the file beside an artifact is `<app>.spdx.json`. It now passes
`sbom::application_name(&document)`, the first package, which is the one the document
`DESCRIBES`.

### `src/sbom.rs`

`uuid_from_sha256` takes the first sixteen bytes of the payload digest and sets the two nibbles
RFC 4122 fixes; `build` is a pure function of a manifest, that digest and the packages a Gleam
`manifest.toml` locked. `for_artifact` reads the artifact and, when a project was named, its
`manifest.toml` — a *missing* manifest is the `NOASSERTION` case rather than a failure, because
a project that has never resolved its dependencies is in exactly the position
`ginary sbom <exe>` is in, while a manifest that is there and unreadable is a document the run
was supposed to use and is an error. `LockedPackage` deliberately does not deny unknown fields:

### `src/doctor.rs`

`probe_cache_dir` is a real probe: `create_dir_all`, write `#!/bin/sh\nexit 0\n`, chmod 0755,
spawn it, and remove the file before returning whatever the answer was. `access(2)` reports the
mode bits and says nothing about the mount, and `noexec` is the failure users actually hit — it
is exit 125 at run time. The directory is created when it is missing, because that is what a
launch does and reporting "not writable" for a cache nobody has used yet would be reporting its
absence. A program that starts and exits non-zero still proves the mount allows execution, so
only a failure to *start* is an answer of `no`.

`project_context` reads the `gleam.toml` twice, and that is the point. `ProjectConfig::from_toml`
refuses a manifest whose `[tools.ginary]` holds an unknown key — which is exactly the case this
report exists to describe — so the project's identity is read from a permissive `RawManifest`
and the table's status from the strict parser. `ConfigStatus::Absent` and `ConfigStatus::Ok` are
told apart by whether the raw read saw a `[tools.ginary]` at all, because the strict parser fills
in defaults and cannot tell "no table" from "empty table".

`native_objects` walks the shipment depth-bounded and never through a directory symlink, takes
only files under a `priv` component, and decides by magic and never by extension. `crypto_report`
finds `<root>/lib/crypto-*/priv/lib/crypto.so` by prefix and calls its OpenSSL statically linked
when every `DT_NEEDED` is in `C_RUNTIME_LIBRARIES`.

`Report::render_text` grew three optional blocks — the cache probe, the crypto note, and the
project — each appended only when it is `Some`, so the existing unit tests that build a `Report`
with `None` for all three are unchanged and still pass.

### `formal/Cache.tla`, and what TLC found

The model is two launchers, two cache keys and one pruner over one application directory. Entry
states are `Absent`, `Complete` and `Trashed`, with `TmpPartial` derived — a partial extraction
is a *sibling* of the entry, `.<key>.tmp-<pid>`, so it is a set of process ids per key and a key
can be `TmpPartial` and `Complete` at once. `docs/dev/formal.md` maps every action onto the
function that performs it and lists what the model abstracts away: `mtime` and the prune age,
`fsync` and `syncfs`, filesystem atomicity, error paths, and identity across restarts.

**TLC found two violations, and both were the model.** Each was minimised from the trace TLC
printed and each is recorded here because a model that was only ever run once it was right is a
model nobody can trust.

*Violation 1 — `I2`, at depth 8.* The first form of I2 was
`pc[p] = "Running" => entry[key[p]] = Complete /\ p \notin tmps[key[p]]`. TLC produced: `p1`
begins extracting `k1`; `p2` begins extracting `k1`; `p1` crashes, leaving its tree; `p1`
restarts; `p2` finishes and renames; `p1` hits the now-complete entry and locks it — and `p1` is
still in `tmps[k1]`, from the life it crashed out of.

The code is right and the invariant was wrong. A launcher runs out of `<app>/<key>`; the
leftover is `<app>/.<key>.tmp-<pid>`, a different directory, and `entry[key[p]] = Complete` is
already the whole of "not a partial tree". The second conjunct was conflating two paths. I2 is
now `StateOf(key[p]) = Complete /\ renames[key[p]] = 1`, which keeps it from being I1 restated:
it says the rename is the completion marker and there is no other one, so an entry that arrived
any other way could not be launched from.

*Violation 2 — `I3`, a liveness counter-example with a 13-state lasso.* `p1` crashes mid-extract
on `k2` and restarts; from then on the cycle is `p2` crashing, restarting and sweeping, and `p1`
never sweeps its own leftover, so `tmps[k2] = {p1}` forever. `SF_vars(Sweep)` is satisfied the
whole time, by somebody else's sweeps.

Again the model. `cache::sweep` keeps a tree when `pid != self_pid && is_alive(pid)`, and a
restarted application is a *new pid* — the operating system does not reuse the identity the way
the model does, so the leftover's pid is dead and any sweep removes it. The model's `Sweep` was
reading "alive" as the model's `alive` flag rather than as what `is_alive` actually decides. It
now takes the whole directory in one pass, as the code does, keeping only `InUse(q, k)` —
`alive[q] /\ pc[q] = "Extracting" /\ key[q] = k`, a tree somebody is extracting into right now.
I3 was restated over `InUse` for the same reason.

The fairness was then trimmed to exactly what I3 needs — `FinishExtract`, `TakeSharedLock`,
`ReleaseOnExit`, `Restart` and `Sweep`, all strong — after the first formulation, which had a
strong-fairness conjunct for every action and every `(p, k)` pair, ran for over ten minutes in
TLC's temporal phase without finishing. `Hit`, `BeginExtract` and the two prune actions are
deliberately unfair: nothing obliges anybody to run the application again, and housekeeping that
never runs leaves a cache that is larger than it needs to be rather than one that is wrong.

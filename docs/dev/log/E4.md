### 2 — `sha2` 0.10.9 -> 0.11.0

`Cargo.toml`:

```toml
sha2 = { version = "0.11.0", default-features = false }
```

`Cargo.lock` moves the whole RustCrypto stack with it, and each package resolves exactly
once:

| package | before | after |
|---|---|---|
| `sha2` | 0.10.9 | 0.11.0 |
| `digest` | 0.10.7 | 0.11.3 |
| `block-buffer` | 0.10.4 | 0.12.1 |
| `crypto-common` | 0.1.7 | 0.2.2 |
| `cpufeatures` | 0.2.17 | 0.3.1 |
| `generic-array` | 0.14.7 | *(gone)* |
| `version_check` | 0.9.5 | *(gone, it was `generic-array`'s build dependency)* |
| `hybrid-array` | — | 0.4.14 |

`digest` 0.11.0 itself is yanked — 0.11.1 introduced breaking changes the RustCrypto
authors decided could not ship as a patch — so the lockfile resolves 0.11.3, which is the
first line anyone should be on.

`default-features = false` is deliberate and is the only judgement call in the bump. 0.11
removed the `std` feature (nothing here ever asked `sha2` for an `Error`) and made `alloc`
and `oid` the defaults. `oid` exists to hand out an X.509 object identifier and pulls
`const-oid` into the graph to do it; `alloc` exists for the boxed `DynDigest`. ginary
hashes bytes and prints hex, so both are dropped, and `const-oid` never enters the tree.
That matches how `object`, `zstd`, `toml` and `rustix` are already spelled in this
manifest, and it keeps the launcher-only stub — which carries `sha2` unconditionally — as
small as it was.

**No call site changed, and that is a result rather than an omission.** The breaking half
of `digest` 0.11 is real but lands elsewhere: `generic-array` replaced by `hybrid-array`
(so `Output<Sha256>` is `hybrid_array::Array<u8, U32>` now), `digest::core_api` renamed to
`digest::block_api`, the `io::Write`/`io::Read` impls removed in favour of
`digest_io::IoWrapper`, `Mac::new`/`new_from_slice`/`generate_key` removed, the `std`
feature removed, `VariableOutput` removed. The `Digest` trait's own shape — `new`,
`update(impl AsRef<[u8]>)`, `finalize() -> Output<Self>`, `finalize_reset`, `digest` — is
unchanged, and the two conversions this crate leans on survive the array swap: `Array<u8,
U32>` is still `AsRef<[u8]>`, so `hex::encode(hasher.finalize())` still spells a digest,
and `[u8; 32]: From<Array<u8, U32>>` still holds, so `.finalize().into()` still fills a
`[u8; 32]`.

Every one of the crate's uses is in that unchanged subset, so the audit was to check all
of them rather than to rewrite any:

| file | what it does |
|---|---|
| `src/payload.rs` | `Sha256::new()` / `update` / `finalize().into()` on both the hashing writer and the hashing reader |
| `src/manifest.rs` | `Index::from_staged`'s per-file loop: `new`, `update`, `hex::encode(finalize())` |
| `src/download.rs` | the streaming digest of a fetched body, `finalize().into()` |
| `src/catalog.rs` | the same over a tarball on disk, `hex::encode(finalize())` |
| `src/verify.rs` | the deep check's file digest, and `Sha256::digest` in its unit tests |
| `src/inspect.rs` | the payload digest an artifact is checked against |
| `src/sign_macos.rs` | `finalize_reset()` per page of the Mach-O code directory |
| `tests/common/payload.rs`, `tests/common/repack.rs`, `tests/verify.rs` | the same three calls from the test side |

Nothing was papered over: there is no `as` cast, no wrapper, and no
`#[allow]` anywhere near the change. `std::io::copy` into a hasher — the one idiom the
removal of the `io::Write` impl would have broken — appears nowhere; every digest in this
crate is a hand-written read loop, which is why the removal costs nothing.

The one thing that had to be true is that not a byte of any digest moved, because these
digests are on-disk format: the trailer's `payload_sha256`, every `sha256` in
`ginary.index.json`, and every catalog entry digest. `tests/digest.rs` was written for
this in RED, against 0.10.9, with every constant checked by hand against `sha256sum`
first. Under 0.11.0 all six pass unchanged, the insta snapshot included:

### 3 — the pre-push gate, run unmodified

The hook is the global one E4's housekeeping section already identified:
`core.hooksPath = ~/.config/git/hooks`, whose `pre-push` sources
`~/.config/git/hooks/renovate-freshness.sh` and calls `renovate_gate "$remote"
"$push_input"`. `renovate_gate` runs `renovate-local` — the official Renovate image, pinned
by digest, `--platform=local`, read-only, over a `git checkout-index` snapshot of the
**index**, so only staged content is examined — and refuses the push when a dependency the
push touched has a non-major update.

Running the gate is therefore running that function with the ref line a first push of
`main` to an empty remote produces. No environment variable was set, no git config was
changed, and the script was not edited:

```console
$ . ~/.config/git/hooks/renovate-freshness.sh
$ renovate_gate origin "refs/heads/main $(git rev-parse HEAD) refs/heads/main $(printf '0%.0s' {1..40})"
>>> renovate gate: dependency manifests changed — checking the touched dependencies...
 WARN: GitHub token is required for some dependencies (repository=local)
::error:: push refused: this push changes dependencies that are not on their latest non-major release:
  .github/workflows/ci.yml: rust 1.88.0 -> 1.98.0 (minor)
```

`sha2` is gone from the report and twelve of the thirteen toolchain sites with it. What is
left is the `msrv` job's own pin, and it is the gate misreading a floor as a dependency:
Renovate's `rust-version` datasource sees `toolchain: 1.88.0`, offers 1.98.0, and taking
that offer is precisely the change that would stop the job proving anything. Raising it
would also contradict `rust-version = "1.88"` in `Cargo.toml` and fail

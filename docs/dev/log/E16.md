### 10.2 — a seventh glibc-only assertion, in a shape the scanner cannot see (medium). VALID.

*Claim:* `tests/stage_run.rs::the_needs_line_lists_the_libraries_the_runtime_loads` asserts
glibc's four sonames and a `(GLIBC_` floor on *any* ELF host, so it fails on musl Linux; the sweep
that gated six others missed it because it branches on `object_format` at run time rather than
carrying a `cfg` attribute.

*Evidence.* `src/platform.rs`'s `object_format` maps `Os::Linux => ObjectFormat::Elf` with no C
library in the question — that is its whole job — and the test's ELF arm named `libc.so.6`,
`libtinfo.so.6`, `libstdc++.so.6`, `libgcc_s.so.1` and then asserted `needs.contains("(GLIBC_")`.
On Alpine the host `erl` names `libc.musl-<arch>.so.1` and carries no symbol versions, so the test
fails against a machine with nothing wrong with it. `gnu_gate_sites` cannot see it: it requires
`attributes.contains("target_os = \"linux\"")` and this test carries no attribute at all.

*RED.* The rule is extracted into `common::portability::host_needs_expectation`, a pure function
over a `Target`, so it can be asserted from a host that is not the one it describes;
`tests/regressions/e16_a_glibc_only_expectation_was_asserted_on_any_elf_host.rs` states the correct
rule against the extraction of the old one:

```text
a_musl_host_is_not_expected_to_name_glibc FAILED
assertion `left == right` failed: musl publishes one C library and names it after the
architecture; `libc.so.6` is glibc's own soname and a musl runtime never loads it
  left: ["libc.so.6", "libtinfo.so.6", "libstdc++.so.6", "libgcc_s.so.1"]
 right: ["libc.musl-x86_64.so.1"]
```

*Done.* `host_needs_expectation` keys the expectation on the object format **and** the C library:
glibc's four names with a floor for gnu; `libc.musl-<arch>.so.1` and no floor for musl, because
which of `libstdc++`, `libgcc_s` and a terminal library an Alpine `erl` links is a packaging
decision this project has no business pinning; `kernel32.dll` folded for a PE; `libSystem` for a
Mach-O. `tests/stage_run.rs` reads it instead of writing the names a second time, and the floor
assertion is asserted in both directions, so a `(GLIBC_` on a musl host is a failure rather than a
silence.

*The scanner keeps its narrow rule, and now says so.* Widening `gnu_gate_sites` to report every
ungated `#[test]` holding a `GLIBC_CLAIMS` needle would report a pure unit test over literal
input, which asserts nothing about a host and is not a defect. Its doc comment records the
boundary and names where the runtime shape is answered instead.

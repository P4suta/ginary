## Housekeeping

One behavioural fix carried over from the A1c review, made before any A2 product code was
written. It closes the remaining half of A1c's first finding, so the milestone starts from a
tree where the symlink rules `docs/dev/architecture.md` describes are the rules the code
applies.

### 1 — a symlinked `ebin` or `priv` still reached an excluded directory (low)

A1c's fix round closed one half of this and the review that followed it recorded the other half
as owed. `copy_subtree` stats its `from` with `symlink_metadata` before reading anything out of
it, so an `ebin` or a `priv` that is *itself* a link is no longer followed blindly. But it put
that link through `resolve_link`, which enforces only the *file* boundary: the target has to be
inside the application directory. The *directory* boundary — a link to a directory may not leave
the `ebin` or `priv` it was found in, which is what stops `ebin/sources -> ../src` from staging
the sources that `assemble::EXCLUDED_APP_DIRS` exists to leave behind — was applied to every
entry found inside an `ebin` or `priv` and to neither of those two directories themselves.

An `ebin` or a `priv` has no enclosing subtree to be held to, so it was held to the weaker
boundary alone, and an application whose `priv` *is* a symlink to its own `src` passed: the
target is inside the application, `read_dir` follows it, and the whole of a directory that never
travels was copied into the artifact under the name `priv`. Staging exited zero and said
nothing. It is the same silent leak the A1c fix exists to prevent, with the application's own
source tree in place of the build machine's.

**The regression test, written first.**
`tests/regressions/a2_a_symlinked_priv_reached_an_excluded_directory.rs` covers four shapes over
one fake shipment application that has the `src` a real
`gleam export erlang-shipment` leaves beside `ebin`, plus a non-excluded `assets` sibling:
`priv -> src`, `priv -> src/data`, `ebin -> src`, and — as the control that keeps the fix from
becoming a blanket ban — `priv -> assets`, which A1c deliberately allows and which must still
stage. Before the fix, three of the four failed, and the staged listing in the failure output is
the leak itself:

The fourth, `priv -> assets`, passed before the fix and still passes after it.

One detour is worth recording, because it is a trap for the next test that writes a symlink by
hand. The first draft linked `priv` to `"../src"`, reading the target from the point of view of
the directory the link *replaces*. A relative symlink resolves against the directory that holds
the link, and the link is at `<app>/priv`, so `../src` names `<shipment>/src`, which does not
exist. The link dangled, `closure` therefore reported no `priv` at all, `copy_subtree` was never
called, and all four tests failed for a reason that had nothing to do with the bug. The targets
are written relative to the application directory — `src`, `src/data`, `assets` — and the tests
then failed for the right reason.

**The fix.** `copy_subtree` now applies the second boundary to the link it was handed. A new
`excluded_component` answers which excluded directory a resolved target reaches, by looking at
the path components below the application root rather than at the last one, so `src`, `src/data`
and anything deeper all answer `src`. A hit is the new `AssembleError::ExcludedSymlinkTarget`,
which names the link, the directory it resolved to, and the excluded name that decided it:

```text
the symlink `<app>/priv` points to `<app>/src`, which is `src` or is inside it; `src` is one of
the directories that never travel, so following the link would stage it under another name
```

The check reads components rather than probing the filesystem, which keeps the rule decidable
from the path alone and keeps it consistent with where the exclusion actually applies. A link to
a directory that merely *holds* a `doc` is not refused, because a real `priv/doc` stages: the
exclusion is a top-level rule, and the fix does not quietly promote it to a depth-independent
one — that is the same over-broad reading a low finding in A1c already corrected in the test
suite.

Two shapes that look like siblings of this one were checked and need nothing. A link out of the
application is still `UnsafeSymlink`, from A1c. A `priv -> ..`, which would stage the whole
application directory, is already refused as `AssembleError::SymlinkCycle`: the copy enters the
application root, meets the `priv` link inside it, and finds the resolved directory in its
`entered` stack. Entries are walked in sorted order, `priv` sorts before `src`, and staging is
atomic in any case, so nothing from `src` reaches the tree.

**Documentation.** Three places described the rule and two of them were describing the intent
rather than the code:

- `docs/dev/architecture.md` said the boundaries "are checked on the `ebin` and `priv`
  themselves as well as on everything under them", which was true of `UnsafeSymlink` and not of
  the directory boundary. The paragraph now says what happens when a link has no enclosing
  subtree to be held to, and names `ExcludedSymlinkTarget`.
- The `src/assemble.rs` module doc said `EXCLUDED_APP_DIRS` "never travels"; it now says it
  never travels under its own name and never under `ebin` or `priv` by way of a symlink,
  whether the link is inside them or is one of them. `copy_subtree`'s own doc comment gains
  the second case, and `stage`'s `# Errors` section gains the variant.
- `docs/dev/testing.md`'s symlink row lists the new file and what it pins, including the
  non-excluded control.

### 4 — three deliberate changes to existing test material

**`DUMMY_BEAM` is now a module rather than a header.** It was the twelve bytes of a bare
`FOR1 <size> BEAM`, which was enough for every milestone that only counted and copied files.
Stripping opens the modules and verifies that none holds `Dbgi` or `Docs` and that every one
holds `Code`; a fake tree whose modules have no `Code` at all could not tell a working
verification from a broken one, and the beam step over a fake runtime would have failed for a
reason that has nothing to do with ginary. It is now forty-eight bytes holding `AtU8`, `Code` and
`Line` — structurally a module, still not loadable, and *already stripped*, so a stub `erl` that
does nothing leaves a tree that legitimately passes. `fake_otp::beam_bytes` is the counterpart:
a test that needs a module carrying `Dbgi` writes one in the open, the same rule the symlink
tests follow.

`tests/snapshots/assemble__stage_explain_table.snap` moved with it, by exactly 288 bytes — eight
modules times thirty-six — and by nothing else. `otp_beam` 36 → 144, `gleam_beam` 60 → 240,
`total` 1319 → 1607, and the six per-application totals by 36 per module. No assertion was
weakened and no other test needed changing.

**`STAGE_FORMAT_VERSION` is 2.** `ginary stage --json` gained a `strip` member and a `report`
member. Adding keys without a bump would have left a consumer written against version one unable
to tell the two shapes apart. `stage_json_carries_the_documented_keys` was updated with it.

**`object` 0.40 is a dependency**, with default features off and `read`, `elf` and `std` on. It is

### 1 — what was implemented

| module | what it does now |
|---|---|
| `src/beam.rs` | `chunks` walks the IFF form under the `FOR1` size bound, `form` unwraps the gzip member `beam_lib` writes, `chunk_ids` and `has_chunk` sit on top of both |
| `src/elf.rs` | `inspect`/`inspect_bytes` dispatch on the class byte into one generic reader over the `object` crate's `FileHeader`; `max_glibc_version` compares component by component |
| `src/strip.rs` | one walk of the tree, then the ELF half and the BEAM half, each verifying afterwards; `StripReport` renders the three-line table |
| `src/report.rs` | `measure` reads `before` from the listing and `after` from the disk, walks the tree for ELF files, and renders the table, the `needs:` line and the warnings |
| `src/assemble.rs` | `StagedRoot::refresh` re-stats the listed files, recomputes the per-application totals and rewrites `ginary.stage.json`, carrying the exclusions, the junk and the boot references over untouched |

`src/cli.rs` needed no change: RED had already wired `ginary beam chunks`, `ginary elf deps` and
`stage`'s five new flags to the stubs, so replacing the stubs is what turned them into commands.
Section 6 of RED recorded them as stub subcommands owed to GREEN; they are now implemented, which
closes that item.

Three implementation choices are worth a reviewer's attention.

**`chunks` never indexes.** The form is bounded once — `form_end = 8 + declared`, refused as
`FormOverrun` if the file is shorter — and every later read is a subtraction inside that bound.
The chunk length is compared as a `u64` against the room that is left, so a `u32::MAX` length on a
32-bit host is a `ChunkOverrun` rather than a wrapped `usize`, and the padding is
`checked_next_multiple_of(4)` clamped to the end of the form, so the padding of a last chunk that
runs into the end of the file is not an error and not a loop.

**`is_shared_object` is `ET_DYN` with no `PT_INTERP`, plus the name.** A position-independent
*executable* is also an `ET_DYN`, and `--strip-unneeded` on `beam.smp` would leave tens of
megabytes on the table; a shared object with `--strip-all` loses its dynamic symbol table and
will not load. The interpreter is the half that separates the two, and the `.so` in the name is
the half that keeps a static executable out of it.

**The report walks the tree for ELF files rather than reading the listing.** The listing says what
staging *wrote*; the `needs:` line is a claim about what is in the directory now. Only the first
four bytes of each file are read to decide, so asking the question does not cost the price of
reading a 10 MB `beam.smp` twice.

### 2 — one thing the RED tests did not know: `beam_lib` gzips what it writes

`beam_lib:strip_release/1` ends in `Stripped = compress(Stripped0)`, and `compress/1` in
`stdlib-8.0.3/src/beam_lib.erl` is `zlib:gzip/1` with no condition on it. Every module in a
stripped staged root is therefore a gzip member wrapping the IFF form, not the form itself, and
the first real run failed exactly there:

```text
---- a_stripped_hello_ffi_fits_in_the_size_budget stdout ----
a real runtime strips: Beam { path: ".../lib/hello_ffi/ebin/hello_ffi.beam",
                              source: NotIff { magic: [31, 139, 8, 0] } }
```

`1f 8b 08 00` is gzip. Four ways out were considered and three rejected:

- *Change the one-liner so `erl` writes uncompressed.* There is no such option, and the argument
  vector is pinned by two tests and by the plan.
- *Skip the verification for a compressed module.* That is the verification's whole point — a
  `strip_release` that answered `{ok, _}` and changed nothing is the failure it exists to catch.
- *Decompress the modules back to bare IFF after stripping.* This would make the artifact bigger
  and pre-empt a decision the plan explicitly defers ("非圧縮で書き直す Rust 製 IFF チャンク
  フィルタは「測ってから」判断", plan line 557).
- **Chosen: unwrap the gzip on read, the way `beam_lib` itself does.** `beam_lib:maybe_uncompress`
  is the same two lines, and the Erlang code server loads gzipped modules without comment. The
  artifact keeps the shape the plan expects; `src/beam.rs` gains `form`, `is_gzipped`,
  `GZIP_MAGIC`, `MAX_FORM_BYTES` and the two error variants `NotGzip` and `FormTooLarge`.

This is the one dependency GREEN added: **`flate2` 1.1.10**, `default-features = false`,
`features = ["rust_backend"]`, so the decompressor is `miniz_oxide` and no C is linked.
`MAX_FORM_BYTES` is 64 MiB, two orders of magnitude above the largest module in an OTP release,
because a `.beam` is a file ginary did not write and an unbounded decompressor is an unbounded
allocation. `cargo deny check` still reports `advisories ok, bans ok, licenses ok, sources ok`,
and its `license-not-encountered` warnings drop from four to three: `miniz_oxide` is
`MIT OR Apache-2.0 OR Zlib`, so the `Zlib` allowance in `deny.toml` is now used.

`docs/adr/0007`, `docs/dev/architecture.md` and `docs/dev/testing.md` all record the fact; the ADR
already anticipated the compression and now says who unwraps it.

## Fix round 1

Ten findings from the A2 review: two high, three medium, five low. All ten are addressed. Every
behavioural one got a regression test that was run and seen to fail for the reason the finding
names before a line of production code moved; the failures are quoted below as they were printed.

### 1 — the staged root was spliced into a `filelib:wildcard` pattern (high)

`beam_lib:strip_release(Root)` is `strip_fils(filelib:wildcard(filename:join(Root,
"lib/*/ebin/*.beam")))` in `stdlib-8.0.3/src/beam_lib.erl:796`. The root is not a path there, it
is the prefix of a *glob*, and `assert_directory/1` passes first because the literal directory
does exist. The module documentation reasoned about Erlang *source* injection — the root travels
after `-extra`, so a quote in a directory name cannot become an expression — and missed that the
value becomes a pattern once it has arrived.

RED, `tests/regressions/a2_the_staged_root_became_a_wildcard.rs`, two trees of one unstripped
fixture module each, side by side:

```text
---- a2_the_staged_root_became_a_wildcard::a_root_named_with_a_bracket_still_has_its_own_modules_stripped stdout ----
panicked at tests/regressions/a2_the_staged_root_became_a_wildcard.rs:80:29:
stripping a root named `out[1]` should succeed: `lib/notify/ebin/gleam@list.beam` still holds
the `Dbgi` chunk after beam_lib:strip_release/1 reported success

---- a2_the_staged_root_became_a_wildcard::a_root_named_with_a_star_leaves_its_neighbours_alone stdout ----
panicked at tests/regressions/a2_the_staged_root_became_a_wildcard.rs:118:5:
assertion `left == right` failed: `out*` reached `outer`, which ginary was never asked to build
```

Both halves of the finding, reproduced: `out[1]` matched nothing and ginary then blamed the
runtime for the chunk it had just reported removing, and `out*` rewrote modules in a sibling
directory ginary was never given.

The fix is `beam_lib:strip_files/1` over the list ginary already walked. `STRIP_FILES_EVAL` is
now `Files=init:get_plain_arguments(), case beam_lib:strip_files(Files) of {ok,_} -> halt(0);
Err -> io:format(standard_error,"~p~n",[Err]), halt(1) end.` and the modules arrive after
`-extra` as paths, one argument each. No glob is involved at any point, and the staged root is
never an argument at all — `no_directory_is_passed_to_the_runtime_where_a_module_belongs` in
`tests/strip.rs` asserts exactly that.

`execve(2)` bounds an argument vector, so the list is split into batches of at most
`strip::MAX_ARGUMENT_BYTES` (256 KiB) of path text. For scale: the whole of the host OTP 29.0.5
installation is 1 355 modules and 130 506 bytes of paths, so a real staged root is one call. Four
unit tests in `src/strip.rs` pin the splitting, including that a path longer than the whole bound
travels in a batch of its own rather than in none.

### 2 — a shared object with a program interpreter was stripped as a program (high)

Three documents said `is_shared_object` was "`ET_DYN` with no `PT_INTERP`, plus the name" — the
module's own doc comment, `docs/dev/architecture.md:275` and this log at "1 — implementation"
above. The code read only `info.interp.is_none()`, because `ElfInfo` carried no object type at
all, and nothing in the suite pinned the choice: `strip(1)` leaves no record of the arguments it
was given, and no test put a shared object into a staged tree.

The equivalence is false in both directions. `strip_arguments` was made public first — the
existing decision, exposed, nothing else changed — so that the regression test could fail on an
assertion rather than on a missing symbol:

```text
---- a2_a_shared_object_with_an_interpreter_was_fully_stripped::a_shared_object_that_has_an_interpreter_keeps_its_dynamic_symbols stdout ----
panicked at tests/regressions/a2_a_shared_object_with_an_interpreter_was_fully_stripped.rs:61:5:
assertion `left == right` failed: /lib/x86_64-linux-gnu/libc.so.6 is a shared object;
--strip-all would take its dynamic symbol table
  left: ["--strip-all"]
 right: ["--strip-unneeded"]
```

`ElfInfo` now carries `kind: ElfKind` read from `e_type`, and a shared object is an `ET_DYN`
whose name is a library's *or* which has no interpreter — a position-independent executable is an
`ET_DYN` too, has an interpreter and is not named `libfoo.so`, so it still gets `--strip-all`.
The rule is pinned three ways: the regression test over the host `libc.so.6` and the running test
binary, and `a_shared_object_in_the_staged_tree_is_stripped_and_still_loads_its_dependencies` in
`tests/strip.rs`, which stages a real shared object, strips it and asserts its `DT_NEEDED` list
survived. `kind` also appears in `ginary elf deps --json`.

### 3 — a `.beam` outside `lib/<app>/ebin` was verified and never stripped (medium)

The same wildcard, from the other side: ginary counted, measured and verified every `.beam` in
the tree, and `strip_release/1` rewrote only what the glob matched.

```text
---- a2_a_module_outside_ebin_was_never_stripped::a_module_under_priv_is_stripped_like_one_under_ebin stdout ----
panicked at tests/regressions/a2_a_module_outside_ebin_was_never_stripped.rs:82:29:

```

Fixed by the same change as finding 1: the set ginary verifies is now the set it handed over.
`a_module_outside_an_ebin_is_handed_to_the_runtime_like_any_other` in `tests/strip.rs` asserts it
without a real runtime, by reading the stub `erl`'s argument log.

### 4 — the gzip branch of `src/beam.rs` had no test outside the gated e2e (medium)

`form`, `is_gzipped`, `GZIP_MAGIC`, `MAX_FORM_BYTES`, `BeamError::NotGzip` and
`BeamError::FormTooLarge` were reachable only from `tests/stage_run.rs`, which is gated on
`gleam` and `erl` — so on a machine with no toolchain, the machines the never-panic policy exists
for, the branch and its 64 MiB bounded allocation were untested. `docs/dev/testing.md` states the
policy this violates in the same change that added it.

`flate2` is now in `dev-dependencies` — the same crate `src/beam.rs` already decompresses with,
so nothing new enters the tree — and `tests/beam.rs` gained seven tests: a gzipped module reading
identically to the form inside it, `chunk_ids` over a stripped module on disk, the uncompressed
case still borrowing rather than copying, a member cut short, the magic followed by rubbish, a
small member that expands past the limit, and one that expands to exactly the limit. The
never-panic table gained `chunks_never_panics_on_almost_a_gzipped_beam_file`, which fixes the two
magic bytes and randomises the rest.

These seven passed on the first run. That is the honest record: the finding was missing coverage,
not a defect, and the tests are the fix. `tests/beam.rs` went from 24 tests to 32.

### 5 — an unparseable ELF-magic file failed the whole stage (medium)

`report::measure` says in its own doc comment that a file which starts like an ELF and cannot be
parsed is a warning rather than a failure. `strip_elf` took the same file and returned
`StripError::Elf` from a bare `?`, before `strip` had even been looked for.

```text
---- a2_an_unreadable_elf_file_failed_the_whole_stage::four_bytes_of_elf_magic_are_a_reported_skip_and_not_a_failure stdout ----
panicked at tests/regressions/a2_an_unreadable_elf_file_failed_the_whole_stage.rs:43:29:
one unreadable file must not fail the stage: cannot inspect
`/tmp/.tmphiZdEq/out/lib/notify/priv/data.bin`
```

`StripReport` gained `warnings: Vec<String>`, printed under the table as `warning: <line>` and
carried in both JSON shapes; the file is skipped and named, which is the decision `report.rs`
already made about it. The three error variants the finding noted were pinned nowhere are now
pinned by their messages — `a_strip_that_fails_on_a_file_names_the_file_and_quotes_the_tool` and
`a_strip_that_destroys_a_file_says_which_and_how` — so ADR 0007's "names the file and quotes the
tool's standard error" is a test and not a promise.

### 6 to 10 — the five low findings

- **`jq '.report.needs_summary'` does not exist.** `SizeReportPayload` flattens the report, so
  the key is `.needs_summary`. `docs/dev/debugging.md` now prints the working path and says
  explicitly that the two JSON shapes nest differently and why.
- **The `ginary beam chunks` transcript was invented.** Replaced with the real output of
  `ginary beam chunks tests/fixtures/beam/gleam@list.beam` — a fixture that is in the repository,
  so the block is reproducible.
- **`--report` conflicted with `--json` as a flag.** `ginary stage --json --report text` — the
  documented default, spelled out loud — was a usage error, and `--report json --explain` was
  accepted and then silently ignored. The conflict moved onto the *value*: `cli::value_conflict`
  returns the message, `run` hands it to clap so the exit status stays 2, and there are now tests
  for all three combinations plus two unit tests over the rule itself.
- **`with_failing_erl_script` interpolated its term into a single-quoted shell string.** A `~p`
  of a quoted atom holds apostrophes and would have written a stub that fails to parse. The term
  now travels in a file beside the stub, and the test that asserts ginary quotes the term passes
  `{error,beam_lib,{not_a_beam_file,'Elixir.Notify'}}` to prove it.
- **`stage_rewrites_the_listing_so_its_sizes_match_the_stripped_tree` was vacuous.** The stub
  `erl` changed no bytes, so every size already matched and the test would have passed with
  `StagedRoot::refresh` deleted. `FakeOtp::with_shrinking_erl_script` installs a stub that
  overwrites every `.beam` it is given with a smaller module that still holds `Code`; the test
  now asserts that at least one file did shrink, so it cannot pass by accident again.

### What the earlier sections of this log got wrong

Two statements above this line were true of the intent and not of the code, and are left in place
because this file is a record rather than a description:

- "**`is_shared_object` is `ET_DYN` with no `PT_INTERP`, plus the name**" described a rule the
  code did not implement; `e_type` was never read. Finding 2 is where it became true.
- The `beam_lib:strip_release/1` one-liner quoted under "1 — implementation" is no longer what
  ginary runs. Finding 1 replaced it with `strip_files/1` over an explicit file list.
